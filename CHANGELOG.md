# Changelog

Notable user-facing changes to pdfvision are documented here.

## [Unreleased]

### Added

- Added the `text_row_vector_bars` page warning (needs `--layout`; always on in `read_pdf`) for coloured bars stacked in text rows whose start, length or colour carries what the text does not: a Gantt chart's task bars and status colours, a horizontal bar chart. Pages with a few such marks stayed below `dense_vector_graphics` and read cleanly while the answer was only in the bars. The evidence is narrow — filled non-white bars, at least four rows of one height, no text inside, varying like encoded values — and it fired on 7 of 6,562 pages of a real-PDF corpus, all bar charts. The message names the rows, scale and legend to `--render-region`.
- Named the repeated page chrome that `--strip-repeated` (and `read_pdf`, which always strips it) removes: the Markdown document header gains one `Repeated page chrome (removed from page bodies)` line listing up to eight distinct stripped strings (those on the most pages, each clipped at 100 characters) with the number of pages that carried each, then a count of any further strings, and folding strings that differ only in digits (`"Page 1 of 4" … "Page 3 of 4"`). A footer such as `Confidential — internal use only` or a browser print date and source URL was dropped from every page with nothing saying so.
- Added `markedText` to Highlight, Underline, Squiggly, and StrikeOut annotations (`--annotations`, and the Markdown `Marked Text` column): the page text under the markup's quads, read from glyph positions so only the covered words are reported. A strike-out over `1.5% per month` inside a longer sentence now says so instead of giving only a box. Absent when no glyph sits under the markup or the page's glyphs cannot be placed.
- Listed in the official MCP Registry as `io.github.yamadashy/pdfvision`; the npm-publish workflow now publishes `server.json` after each release.
- Added `column` (and `columnSpan`) to every `layout.tables[].rows[].cells[]` entry, and a `layout_table_uncertain` page warning with a `tableIndex` field. Columns are derived from where the body cells sit, so a row with an empty cell keeps its later values in their own columns; header and merged cells are placed on the columns their text overlaps, with a `columnSpan` when that is more than one, so a centered group header narrower than its group covers only the columns under its text. The warning fires when a table's geometry does not resolve into one grid — a line with numbers inside the table that no row claimed, two values in one column of a row, neighbouring columns that no row fills together, or a row with values but no label that label text overlaps from the line above or below (a label set in two lines around its values) — and names the table bbox to render.
- Added the `text_matches_background` page warning (severity `warning`) for native text filled in the colour of what is painted behind it — white text on a white page, or text the colour of the box under it — which a reader sees as blank space. It fires only where the background is provably known (an opaque device-colour rectangle or the bare page), and stays silent over images, gradients, complex shapes, and pale-but-visible text such as watermarks. It is a warning rather than an error because the commonest real cause is invisible production metadata (the GPO slug on every Federal Register page) rather than concealment. The message names up to three passages with a bbox each for `--render-region`, and the bbox enclosing all of them when there are more. ([#249](https://github.com/yamadashy/pdfvision/issues/249))
- Added a `symbol_font_substitution` page warning for signs set in a separate symbol font whose character map reports them as ordinary characters, as some journal toolchains do: `−52%` extracted as `252%`, `p < 0.001` as `p , 0.001`, `7.1 ± 0.9` as `7.1 þ 0.9`, with nothing on the page flagging it. It fires when one font is used only for single glyphs set inline at body size beside numbers in another font and at least two of them extract as a digit or Latin-1 letter (commas and periods alone never fire it, since TeX sets math-mode decimal points and commas from its math-italic font), and names the font, the extracted characters, samples in context, and a `--render-region` (clipped to the page) covering the runs beside numbers — a number written without its leading zero, as in `p < .001`, counts. The PDF states the wrong characters, so the text itself is left as extracted. ([#266](https://github.com/yamadashy/pdfvision/issues/266))
- Added the `vector_chart_labels` page warning for vector charts whose text labels the layout pass now keeps together: it names the chart region (`--render-region x,y,w,h`) and says the labels are read as a group, bar by bar over vertical bars, otherwise row by row, while which value belongs to which bar, series or category is shown only by the drawing. It fires when a cluster of vector paths with bars (text-free marks of one width standing side by side on one baseline, with different lengths) holds short, largely numeric labels and a word, and no layout table already covers it; gridded and ruled tables, line charts and callout diagrams do not fire it. ([#256](https://github.com/yamadashy/pdfvision/issues/256))

### Changed

- `pdfvision docs warnings <code>` prints the entry for one warning code — what it means, when it fires, its limits, and the next step — in a few hundred bytes to ~4 KB, and accepts several codes at once. `pdfvision docs warnings` is now a ~15 KB topic (down from ~53 KB): the shape, how to read severity, an index of every code with a one-line gloss, and the density Overview and raw signals. An agent holding one code used to pay roughly 12k tokens for the whole catalog. An unknown code exits 1 and names the closest codes; a bare `pdfvision docs <code>` and the singular `docs warning <code>` resolve too. ([#287](https://github.com/yamadashy/pdfvision/issues/287))
- `large_raster_low_text_overlap` now ends with the next step, like its neighbours: `render that region (--render-region x,y,w,h) or OCR the page (--ocr) to read it`, with the image's own region clipped to the page (the union of the tiles for the tiled-image form). It used to stop at the diagnosis, leaving an agent that follows warning text with nothing to do on a slide whose content is a screenshot.
- Documented the automatic attachment, JavaScript, and outline presence counts, including their source-document scope and the flags that expose details.
- Updated the search-and-zoom guide to distinguish a match's tight `bbox` from the compact report's crop-ready `region`, then pass that region unchanged to `--render-region`.
- Added site guidance for inspecting searchable native text that is invisible or covered by a later opaque fill, including the limits of these warnings and rendered-page verification.
- Corrected the search documentation to describe ruby-inclusive and ruby-stripped native matching, narrow cross-line joins for hyphenated terms and stacked labels, and vertical CJK body-column reading order.

### Fixed

- Kept more of `layout.tables[]` together. A cell wrapped over several lines at its own line pitch is joined to its row instead of being dropped; rows the aligned-text pass found past the end of the numeric table it matches are kept (a parts list read as its 3-row header now carries its 30-odd part rows); a table that stars every coefficient keeps its trailing `Yes | No` rows; a header with one single-letter column (`N`) splits into cells; and a caption (`Table 1 (continued)`) is no longer folded into a cell or kept as a row, while words such as `Tableware` or `Tablets` are no longer read as captions. On a real-PDF corpus 37 of 6,562 pages changed tables, nearly all by gaining rows that had been silently lost.
- Read framed and tinted boxes, bands between matching horizontal rules, and vector figures as one unit in the layout reading order. A boxed warning's body was emitted after the page footer, away from its heading, because its indented lines formed a "column" of their own (manual quick-start: `WARNING — Risk of scalding` / `EN Unplug the base…` / footer / `Never open the lid…`); the box's outline now keeps its heading and body together where the box is ([#263](https://github.com/yamadashy/pdfvision/issues/263)). A booktabs table is a band between its rules: its cells read row by row instead of column by column, and a footnote that shares the table's left edge is no longer read between two of its columns ([#257](https://github.com/yamadashy/pdfvision/issues/257)). A vector chart's ticks, legend, values and category names stay together before its caption instead of trailing the column as a flat run after unrelated prose, read bar by bar over vertical bars and chart by chart on a panel of several charts ([#256](https://github.com/yamadashy/pdfvision/issues/256)). As a result, gridded and ruled tables, invoices and form grids read row by row in the body (a datasheet pin table now reads `OUT A 1 8 V+` rather than one column after another); on a form whose value boxes are drawn apart from their label boxes, an occasional value can still land after the wrong label.
- Read a column interrupted by a photo, pull quote or sidebar to its end before the next column. Text run around an inset photo (a narrower band inside the column) was read after the whole column, and a stray word or jump line inside a column ended the column run, so every column was read segment by segment and sentences that continue across the interruption came out about 50 lines apart (magazine feature: `…six divers and a borrowed boat. Each` / `weekend they cleared urchins…`). A narrowed band is now read in its place, a fragment inside one column's band joins that column, and the last word of a justified line cut off by wide word spaces is put back on its line (`The counting`). A full-width block now cuts only the columns it crosses, and lines of two side-by-side prose runs that arrive alternately in the stream are rebuilt into one block each, so a sidebar beside a full-width abstract is read after the abstract instead of line by line; `reading_order_divergence` stops calling that layout order unreliable where the weave is gone. ([#274](https://github.com/yamadashy/pdfvision/issues/274))
- Marked superscripts and subscripts instead of flattening them into the neighbouring text. An exponent, an index or a footnote marker is a smaller run on a shifted baseline, and it was joined as ordinary characters, so `2.3 · 10^19` read as the number `2.3 · 1019`, `|∇f|²` as `|∇f|2`, and the subscript of `P_drop` landed on a line of its own. Such a run touching the text before it (or opening a line, as a footnote marker does) is now written as `^x` / `_x` for one character or a digit run and `^{…}` / `_{…}` otherwise (`10^19`, `P_{drop}`, `e^{−f}`, `u_j^{n+1}`, `^1 Measured on…`), in `pages[].text`, layout text, spans and search alike. Small caps, ruby, raised marks that read the same either way (`*`, `†`, `※1`, `®`, `[4]`) and small print beside larger text are left alone. Unicode superscript and subscript characters, which NFKC normalization folded into plain digits (`m²` → `m2`), are written the same way (`m^2`). ([#241](https://github.com/yamadashy/pdfvision/issues/241))
- Decoded check marks, crosses, bullets and symbols set in the standard ZapfDingbats and Symbol fonts. pdf.js maps glyph names through the Adobe Glyph List, which has no entry for ZapfDingbats names such as `a19`, so without a ToUnicode map a ✓ came back as its character code `3` and a ✗ as `7` — in a table of numbers, a plausible value. Codes pdf.js passed through unmapped in one of these fonts are now decoded through the font's /Differences or built-in encoding (`3` → `✓`, `l` → `●`). Lone check and cross marks count as table values, so a yes/no column keeps its table rows. ([#275](https://github.com/yamadashy/pdfvision/issues/275))
- Stopped putting a space between every letter of letter-spaced text. pdf.js inserts a space wherever two glyphs are more than about a tenth of an em apart, so headings set with character spacing came back as `B A C K G R O U N D` and `P H Y S I C A L R E V I E W L E T T E R S`. Words the operator list shows were drawn with character spacing and no space glyph are now rejoined (`BACKGROUND`, `PHYSICAL REVIEW LETTERS`), keeping the spaces that were real space glyphs. A justified Japanese line set one character per text item (`る と 判 断 す る …`) is joined when its characters sit at one uniform pitch and a tightly set line of the same size spans the same measure next to it, so a calendar header or a row of single-character table cells stays apart. ([#268](https://github.com/yamadashy/pdfvision/issues/268))
- Read text that is painted several times to fake bold once. Older Word/Excel-to-PDF workflows draw a run two to five times with sub-point offsets; pdf.js returned every copy, and because it merges the last copy of one run with the first copy of the next, the title of a listed company's 決算短信 came back as `22222000002222255555年3月期年3月期…決算短決算短…信信信信信` and a search for 「決算短信」 found nothing. Copies of the same text in the same font and size on the same baseline, within a fraction of a glyph of a run already read, are now dropped, and an item that begins or ends with such a copy keeps only its new part: `2025年3月期 決算短信〔IFRS〕(連結)`. ([#267](https://github.com/yamadashy/pdfvision/issues/267))
- Paired form fields with labels printed far to their left. A left label was searched only within 80 pt of the field, so on a form with a label column at the left margin and the field column at x=200 most fields had an empty `Label` (`full_name`, `email`, `county`), and only fields with long labels got one. A label on the field's own row is now taken at any distance when no text or widget lies between them, and the second and third boxes of a split date take the label printed before the first box.
- Gave each link the text inside its own rectangle. Link text was clipped from whole layout lines by character proportion, and pdf.js merges a navigation bar or a sentence into one line, so adjacent links swapped words (`/money` got no text and `/podcasts` read `Money Podcasts`) and inline links picked up neighbouring words and punctuation (`Halvorsen & Weir counted`, `Cookie Policy.`). Link text is now read from glyph positions; the line-based reading remains only as the fallback for pages whose glyphs cannot be placed.
- Stopped layout lines from running across narrow column gutters. On dense multi-column pages (a three-column register at 8.5 pt with 12 pt gutters, a sidebar 14 pt from the body) a gutter is no wider than the widest justified word spaces, so the per-row gap rule could not see it, and where columns sit on their own baselines a line absorbed the first word or the short last line of the neighbouring column (`transferred, sublet or used for a vessel other than level`). Gutters are now found from the whole page — a strip that stays clear line after line while the next column's lines keep starting at the same x, with full prose lines on both sides — and the text on each side is grouped into lines separately, so a line is never joined across one and a bullet or subscript is no longer captured by the neighbouring column's line and stranded on a line of its own. Row-shape signals that split table cells (row width, numeric density) are still read from the page-wide row, so tables inside a column split exactly as before. A layout table whose every column boundary is one of these prose gutters — the page's text columns read across, row by row — is no longer reported; across the survey corpus that removes about 140 such tables, mostly on Federal Register and IRS instruction pages (part of [#242](https://github.com/yamadashy/pdfvision/issues/242)). Text rotated a quarter turn in the page margin (print-production lines on Federal Register and GPO pages, arXiv stamps) is now read after the page body: it was spliced into a paragraph, and as the leftmost block on the page it anchored the first column so that every indented first line was read as a column of its own, tens of lines away from its paragraph. ([#273](https://github.com/yamadashy/pdfvision/issues/273))
- Stopped a lone bullet, warning icon or other symbol set larger than the text from deciding which spans share its line. Line grouping measured a line's height on one representative span and could pick such a symbol, so the next line was pulled into it (IRS Form 941 instructions: `balance due` and `on Form 941` read as one line) or the bullet was left on a line of its own, away from its item. Symbols taller than the line's text are no longer chosen as that span; across the survey corpus lines holding only `•` dropped from 267 to 93, and subscripts more often stay on their line (`mmin`, `ET`).
- Read pages stored with `/Rotate` 90, 180, or 270 the way a viewer shows them. Text was grouped along the stored axes, so a landscape table turned sideways in a portrait report came out one displayed column per line, and a vertical Japanese bill on a rotated sheet came out as one- to eight-character fragments with no warning. Lines, reading order, layout blocks and tables, spans, image and vector boxes, visual regions, form fields, links, annotations, structure bboxes, OCR words, search matches, and warnings are now all in the displayed frame, so a rotated page reads like the same page stored upright. **Coordinate change on rotated pages:** `pages[].width` / `height` and every bbox are now displayed-frame values (on a 90° / 270° page, width and height swap), and `--render-region` / `render_pdf` `region` take displayed-frame coordinates, consistent with the rendered PNG. A page whose text is upright only as stored, which `/Rotate` would turn sideways, keeps being read in its stored orientation — and is now also rendered that way — with a new `rotated_page_read_unrotated` warning, which also gives the share of any text set the other way on that page, since that text reads sideways in the stored frame. Unrotated pages are unchanged; cached extractions are invalidated, and PNGs cached by earlier versions are no longer reused (renders now live under a revisioned cache directory, so an old crop cannot come back for a region whose meaning changed).
- Flagged failed redactions inside a line. `text_under_opaque_fill` required a black box to cover 90% of a whole extracted text run, but pdf.js merges a line into one run, so a box over `USD 250,000` inside a sentence went unreported and the value read as ordinary visible text. Coverage is now decided per glyph by replaying the text state from the operator list, and the warning names each covered passage with its bbox (`"USD 250,000" (bbox 389.89,150.78,57.75,10.5)`) instead of a count and a sample; text repainted on top of a box is not reported. Runs whose glyphs cannot be placed keep the whole-span rule. ([#249](https://github.com/yamadashy/pdfvision/issues/249))
- Stopped `reading_order_divergence` from claiming the body was rebuilt in reading order when it was not. On a page with a sidebar or columns sharing baselines with the body, the layout pass can read the side-by-side blocks one line from each in turn, or run one block on into the next column; the Markdown message still said "the body above is that reading order, rebuilt from the layout", and JSON/XML/TOON still recommended `layout.blocks`. When either defect is present the message now says the layout-rebuilt order is unreliable too, names the blocks, and tells the reader to render the page. The reading order itself is unchanged on these pages ([#273](https://github.com/yamadashy/pdfvision/issues/273), [#274](https://github.com/yamadashy/pdfvision/issues/274)). ([#272](https://github.com/yamadashy/pdfvision/issues/272))
- Fixed `textCoverage` becoming `null` (JSON) or `NaN%` (Markdown) on pages where pdf.js reports a NaN width for whitespace text items; non-finite item sizes are now treated as zero.
- Stopped layout tables from silently shifting values left. Cells were emitted as each row's left-to-right list and rendered left-packed, so in a row with an empty cell every later value landed one column too far left (Attention paper Table 2: `Deep-Att + PosUnk`'s EN-FR BLEU appeared under EN-DE), and headers centered over column groups started in the label column. Markdown now places each cell in its `column` and leaves empty columns empty; XML emits `column`/`columnSpan` attributes. `columnCount` is now the number of geometric columns rather than the widest row's cell count.
- Kept table rows whose empty values are dash placeholders (`—`, `–`, `-`, `n/a`), which were dropped because only one cell looked numeric (Apple 10-K cash flow: `Proceeds from issuance of term debt, net`), and label-only group rows inside a table such as `Net sales:` and `Earnings per share:`, without which repeated sub-labels like `Products` or `Basic` could not be told apart. A currency symbol that pdf.js joins onto the previous value (`$ 29,610 $`) and lettered footnote markers (`(10,246) (b)`) no longer push a value into the neighbouring column or drop a row whose every value carries one (`10 (a)`), and a column header line directly above the first row is kept as a header row instead of being glued onto that row's label.
- Kept a layout table whole when one of its rows is a dash placeholder in every column. Such a row is no evidence of a table on its own, so it was skipped, and the double gap it left broke the row-cadence check: a cash-flow statement with `Restructuring charges | — | —` in the middle came back with no layout table at all. A placeholder row between two rows of the table with its dashes under their values — or in the run of such rows directly above the first numbered row — is now a row of the table. ([#250](https://github.com/yamadashy/pdfvision/issues/250))
- Attached a wrapped table label to the row it belongs to. A label-only line was always folded into the row below, so an invoice item whose name wraps under its first line lost its second half to the next item (`帳票レイアウト変更・結合テスト一式) 会議用弁当(定例打合せ時) ※`). The line now goes to the row it sits clearly closer to — the row above when rows are padded apart and the lines of one cell are not — and stays with the row below, as statements set a label that wraps above its values, when the spacing is even; `layout_table_uncertain` now says so when that even spacing follows a full-width label line, the one case the page cannot settle. Lines wrapped inside any text cell (a "reason" column wrapped around its row line) are joined to their cell the same way instead of being dropped. ([#251](https://github.com/yamadashy/pdfvision/issues/251))
- Kept a table's caption and header row out of its first data cell. A header row of widely spaced single words (`Depot   Region   Planned   Installed`) is kept on one line for reading, so table detection saw one wide line and folded it — with the `Table 1: …` caption above it — into the first row's label, and the columns came out unnamed. The table now sees the header's words as cells, so it becomes a header row with one cell per column; a caption such as `Table 1 (continued)` is never taken as a table row; and header rows that only the aligned-text or single-row pass recognises, such as a `百万円 | %` units line, are kept above a table found from its numbers. ([#253](https://github.com/yamadashy/pdfvision/issues/253))
- Stopped layout tables from ending early and silently leaving out the last rows of the same grid. Rows between two table rows that sit on its grid but are not table evidence on their own — a group heading such as `4 Test & launch`, a task whose dates are still empty — split the table there, and the rest became a second table that the first one's header scan swallowed. Those rows now stay in the table, as do word-valued rows right after it at its row pitch (`County fixed effects | Yes | Yes | No`). Values with significance stars (`-0.142***`), Japanese triangle negatives (`△44,300`), and note markers (`※7 26,269`) now count as values, so their rows are no longer dropped from regression tables and Japanese statements, and a statement whose rows are spread by group headings and wrapped labels is accepted when its value lines keep a regular pitch. A single-row table read from the rows of a table already found is no longer reported as a second, overlapping table. ([#262](https://github.com/yamadashy/pdfvision/issues/262))
- Made MCP search consider extraction warnings from every selected page, including no-hit pages and all-zero searches, so raster-backed text layers and other extraction limits no longer turn a failed exact search into silent evidence of absence. It lists at most five diagnostic pages, prioritizes error-bearing pages, reports the omitted-page count, gives page-based render guidance, and leaves XFA-covered pages to their separate recovery note.
- Preserved compact per-page search diagnostics under `--matches-only`, including warnings and non-OK native or visual quality on no-hit pages and all-zero searches. Applicable XFA placeholder findings now also retain their document-wide unreadable-source scope and correct recovery guidance without restoring full page bodies.

## [0.18.0] - 2026-08-19

### Fixed

- Failed the call, not the process, when OCR language data cannot be downloaded. tesseract.js reports a failed `traineddata` fetch as a worker event rather than a promise rejection, so with no error handler attached the failure was rethrown from a `nextTick` and took the whole process with it: a raw stack and exit 1 on the CLI, and on the MCP server a request that never got a response, a server that exited, and every session ref for every document lost with it. It is now an ordinary error that names the requested language and says its data could not be downloaded — a 404 points at the language code, anything else at the network — and a failure arriving after the worker booted fails that page's OCR instead. Reaching it needs no typo: an offline machine, a proxy, or a CDN outage produces the same event on the first `--ocr` run for a language. The worker thread now ends itself when it reports a boot failure, too — tesseract never settles the promise that would have terminated it, so a long-lived MCP server used to keep one abandoned thread and its WASM heap per failed attempt. ([#185](https://github.com/yamadashy/pdfvision/issues/185))
- Bounded a regex search across pages, not just within one. The per-page 1s budget worked and still let a catastrophic pattern cost pages × 1s — over three minutes on a 176-page document, well past the point where an MCP host gives up and with nothing to show for the wait. A 12s budget on the regex time one request may spend now stops the search, keeps the matches found so far, and warns with the pages searched out of the pages selected and which pages to re-run. Only time inside the search is charged, so extraction and OCR on a slow document cannot spend a budget they had no part in. Like the per-page timeout, the interrupted result is kept out of the cache; in `search_pdf` the summary outranks every other warning and holds a reserved slot, because it is emitted last and a zero from an unsearched page is not evidence of absence. ([#185](https://github.com/yamadashy/pdfvision/issues/185))
- Kept the rest of a search's refs alive when one of them is rendered. `render_pdf` retired a source's whole ref set on every response, so `search_pdf` handing back seven refs and the caller rendering the first left the other six as "Unknown ref" — the advertised search-then-render-the-hits flow worked for exactly one hit, and since the re-run search renumbers from `p1m1`, a cached ref list could then point somewhere else entirely. A response now replaces the set only when it files a new one: a full-page render mints visual-region refs and supersedes what came before, while a region render — every `ref`-driven call included — mints nothing and leaves the set intact. A full page that turns out to have no detected visual region no longer clears the set and files nothing in its place either. ([#187](https://github.com/yamadashy/pdfvision/issues/187))
- Rejected `render_pdf(ref:)` given together with `pages` or `region` instead of silently ignoring them. A leftover `ref` field in a reused call template produced a plausible-looking response for the ref's page, with nothing but the header naming a page the caller had not asked for. The error names which parameter to drop. ([#187](https://github.com/yamadashy/pdfvision/issues/187))
- Stopped `read_pdf`'s truncation notice from suggesting the call that just failed. On a range wide enough that its per-page Overview table fills the response budget on its own — `pages: "1-756"` on the PDF specification — no page body fits, so the dropped pages were the requested pages and the hint read `Continue with read_pdf(pages: "1-756")`: an agent following it looped forever without reaching a line of body text. That case now says the range cannot be served whole and names a single page to start from, or, when one page is already the whole request and still does not fit, points at `search_pdf` instead. The notice also counts page *bodies* now, since the Overview rows for the omitted pages are still in the response — except where the Overview itself is what overflowed, which the #197 entry below covers. ([#188](https://github.com/yamadashy/pdfvision/issues/188))
- Corrected `read_pdf`'s description, which promised that short documents come back whole. "Short" is a page-count threshold while wholeness is decided by the character budget, so a 15-page paper was short by the first rule and truncated by the second — an agent that trusted the description would read the first response as the complete paper. It now says a document under the page limit is read whole and truncated with a continuation hint if it exceeds the budget. ([#188](https://github.com/yamadashy/pdfvision/issues/188))
- Searched checkbox and radio values, which were excluded from every search. `search_pdf` and `--search` advertise the form-field value as a searchable origin, but half the field types never contributed a haystack: a radio whose export value is `りんご` is printed by `read_pdf` and returned zero matches, with nothing in the response to say that the origin had been skipped rather than missed. Checkbox and radio widgets now search their export value — the per-widget on-state name Markdown shows in the Export column, and often the only place an option's wording appears — selected or not, since an unselected option is still an option the document offers. The `Off` state name and hidden or noView widgets stay out, as before. An export value is form metadata rather than artwork, so unlike a text or choice value it does not suppress an OCR hit of the same string elsewhere on the page. ([#189](https://github.com/yamadashy/pdfvision/issues/189))
- Stopped dropping a link-target hit because the page happens to repeat one of the target's words. The suppression was written for the anchor that *is* the URL, where page text and target say one thing twice, but it fired on any native hit of the same string inside the link rectangle: on `Download the full dataset here` → `…/datasets/q3-2026-full.csv`, searching `dataset` silently lost the link hit and the headline count with it — the only place in search where a match was removed rather than counted. Suppression now needs the anchor to restate the target, meaning every word of the visible link text is also a word of the target — and, for a one-word anchor, that the word reads as part of a URL rather than as a label like `Download`. A prose anchor keeps both hits, because the sentence and the hidden target are different evidence. Two link annotations stacked on one rectangle still collapse regardless of anchor, and a link target never suppresses an OCR hit of the same string: the target is not drawn on the page, so OCR reading that string has found a different occurrence. ([#189](https://github.com/yamadashy/pdfvision/issues/189))
- Made a hit's `context` agree with the page body. The context is offered as a quotable preview, but it came from the raw span join that search matches against, and on right-to-left text that join is visibly worse than the reconstruction `read_pdf` prints: the same Arabic sentence came back from `search_pdf` with no inter-word spaces and mirrored parentheses while `read_pdf` showed it correctly, with only the generic `rtl_script_text` warning on both and nothing to say which one to trust. A native hit now quotes the reconstructed layout line, the same text the body shows, and falls back to the old construction where no reconstructed line covers the hit. Layout is already computed on every searched page, so this costs a lookup rather than a pass. ([#189](https://github.com/yamadashy/pdfvision/issues/189))
- Closed the residual duplicate rows left by `search_pdf`'s place collapsing. The crop pads by a fraction of the *match* box, so two hits on one line produced regions differing in the last hundredths of a point — `263.88` against `263.89` — and exact-equality grouping emitted both: ~0.6% of rows over seven documents, 1.9% on one paper. The group key now rounds to whole points, far below any distinction a render could show; the emitted region keeps its precision. ([#189](https://github.com/yamadashy/pdfvision/issues/189))
- Told the caller that a searched page was only a viewer placeholder, on zero hits as well as on hits. `search_pdf`'s per-page warning list is filtered to the pages a hit landed on, so a page could only report that it was unreadable once it had proved it was readable enough to match: on a filled dynamic XFA form whose static layer is one "Please wait..." page, searching for a value visible in the render returned a bare `0 matches` with no mention of XFA, while searching for `Adobe` returned four hits *and* the warning. The unsearchable-page note did not cover it either — the placeholder page carries ~700 characters of well-formed text, so nothing about its native-text quality is suspect. A response now carries one note covering every searched page whose extracted text may not be the page's content at all, hits or not — the code describes the document, so the note speaks for every page selected for the search — named as selected rather than searched, since a regex budget exhaustion can leave some of them unsearched — rather than for the one page it is attached to — and names the recovery that fits the evidence: Adobe Acrobat/Reader for a confirmed placeholder, since a render shows the placeholder too, and a render or OCR pass when the placeholder is only suspected. Pages the note speaks for are dropped from the per-hit warning list and from the no-usable-native-text note, so the response never says it twice or hands back two recoveries that contradict each other. ([#186](https://github.com/yamadashy/pdfvision/issues/186))
- Stopped warning that extraction may be placeholder text on forms where it plainly is not. `xfa_form` fired on the bare `IsXFAPresent` flag, so IRS f1040 and W-9 — 5,000+ real characters, 128 labelled form fields, parsed tables — were told the text they had just extracted might be a "Please wait..." placeholder and that the real content was not extracted. Warnings that are wrong on the common case teach callers to ignore them, which costs exactly the case above. The shapes are now separated using `IsAcroFormPresent` alongside `IsXFAPresent` plus what the pages actually yielded. `xfa_form` at severity `error` requires that no extracted page carries content of its own — text, images, vector drawing, or recovered OCR all count, so a scanned XFA page is no longer told that only Acrobat can help when a render reads it — *and* that a placeholder marker confirmed it. A document with a static field layer is never called a placeholder, which also keeps a narrow `pages` selection from contradicting the whole-document verdict; when that field layer is the only thing extracted — the placeholder page of a fillable form — the new `xfa_fields_only` says exactly that, vouching for the fields it did read without vouching for the page text it did not. Where nothing was extracted and nothing confirms why, `xfa_form` stays at severity `warning` and says exactly that, asking for a render or OCR rather than guessing; the positive claim is reserved for `xfa_static_content`, which fires only when real content was actually extracted. The document map's banner follows the same three-way split instead of telling every XFA reader not to answer from the document. ([#186](https://github.com/yamadashy/pdfvision/issues/186))
- Corrected the two surfaces that still called `search_pdf` a flat hit list — the MCP tool description, which sits in the host's context for the whole session, and the `pdfvision mcp` help line. Since place collapsing ([#179](https://github.com/yamadashy/pdfvision/issues/179)) the response is one row per distinct place with `×N` for collapsed occurrences and an optional `context`, and the response header says so; both descriptions now say the same thing instead of promising a shape the fix removed. ([#195](https://github.com/yamadashy/pdfvision/issues/195))
- Cached OCR language data instead of re-downloading it every run. The `cacheMethod` handed to tesseract.js was `readWrite`, which is not one of the four values it accepts (`write`, `readOnly`, `refresh`, `none`), and its worker script writes the cache back only for `write` / `refresh` / undefined — so nothing was ever written to `<cache-root>/ocr-data/`, while the read path treated the unrecognised value as read-only and found an empty directory. Every `--ocr` run paid a ~10-16MB CDN download per language, on a machine that had already downloaded it, and `clear-cache` had no traineddata to clear; worse, a language that should have been usable offline kept a network dependency, which is exactly the failure [#185](https://github.com/yamadashy/pdfvision/issues/185) hardened against. It now asks for `write` — read *and* write — so the download happens once per language, as the OCR topic has always said. Enabling the write exposed a second fault the previous behaviour had been hiding: the cache adapter is a plain `fs.writeFile`, which truncates the destination before streaming megabytes into it, and the worker thread exits as soon as it reports a boot failure — `eng+jpn` where `jpn` 404s can exit with `eng`'s write in flight, leaving a short file where the next session looks for it and skips the download. That session then fails at `Init`, and tesseract's recovery deletes the cached data for every language the run asked for — so one truncated `eng` costs a failed OCR run plus a fresh download of the `jpn` that was intact. Cached traineddata is now written to a temp sibling and renamed into place, so an interruption — that exit, a Ctrl-C, an OOM kill — leaves the previous file or nothing, never a partial one. ([#194](https://github.com/yamadashy/pdfvision/issues/194))
- Stopped calling a file that is not a PDF a truncated download. The probe behind the parse error only scanned the tail for `%%EOF`, so an HTML login page saved as `.pdf` was reported as likely truncated with advice to re-download it — a retry that returns the identical file every time. A missing `%PDF-` header in the first 1024 bytes now says the file is not a PDF and quotes its printable leading bytes, so the login-page case reads its own diagnosis; a real partial download still gets the truncation hint, which is correct there. ([#190](https://github.com/yamadashy/pdfvision/issues/190))
- Said so when a truncation notice's own premise fails. Counting page *bodies* is only readable because an Overview row for every selected page survives — but the branch that emits that count is reached precisely when the header did not fit: `pages: "1-756"` over the PDF specification came back with 419 of 756 Overview rows, the last one cut mid-row without its closing `|`, under a notice reporting the loss as `756 page bodies omitted` alone. A reader trusting the documented contract concluded it still had per-page detail for all 756. The notice now reads `Overview clipped after page 418` alongside the body count whenever the header itself was clipped, and the clip lands on a row boundary, so the page it names is the last one whose row is actually complete and the Markdown table is never broken mid-row. The recovery guidance — start from a single page, or narrow with `search_pdf` — is unchanged, as is the bodies-only count in every case where the Overview survives whole. The clipped content is now charged for the clip note printed under it, too, so this response fits the budget it names rather than the dozen-odd characters of slack the reserve happened to have left. ([#197](https://github.com/yamadashy/pdfvision/issues/197))
- Rejected `--ocr-lang` given without `--ocr` instead of silently ignoring it. The language is only read once an OCR pass runs, so `--ocr-lang jpn` alone parsed as a complete, successful run that did no OCR at all — exit 0, no warning — and the short help's `--ocr, --ocr-lang <lang>` grouping read as though `--ocr-lang jpn` on its own were a valid OCR request. It now exits with `--ocr-lang requires --ocr`, matching how `--render-scale` treats its missing prerequisite, and the help line no longer presents the two flags as alternatives. ([#202](https://github.com/yamadashy/pdfvision/issues/202))

### Changed

- Emitted one `search_pdf` row per distinct place instead of one per occurrence, marked `×N` when it stands for several. Since a hit's crop grew to the line or table row it sits in, two hits on one line resolved to the same region, so the extra rows were byte-identical apart from a ref that rendered the same image — 21 of 46 rows on one page of the EU AI Act. The distinct matched strings are kept on the surviving row, since `the` / `The`, or two unrelated regex matches, are the one thing that can differ within a place. The headline count still reports occurrences, which is what the caller asked; what changes is that the 100-item cap and its overflow notice now count places, so a search no longer reports itself out of room while covering far fewer than 100 of them. ([#179](https://github.com/yamadashy/pdfvision/issues/179))
- Documented that `--render-scale` without `--render`, `--render-visual-regions`, or `--ocr` exits with an error instead of silently doing nothing. The behavior is not new, but no help line, topic, or site page said so, so the error could only be learned by hitting it.

- Moved the documentation site's hand-written reference content — security egress and cache details, exact library signatures and `onWarning` semantics, schema presence contracts, and MCP parameter caveats — into `docs/cli-topics/*`, so `pdfvision docs <topic>` readers see what only web readers used to. Three site pages carried claims the code does not support and were corrected rather than copied: `pages[].layout.lines` does not exist (lines live under `blocks[].lines`), a symlinked `--attachment-output` path is not refused (only the internal per-document fingerprint directory is checked for that), and the `processFile` example was missing the required `noCache` field.
- Cut the bundled agent skill to a single `SKILL.md` and routed its detail to `pdfvision docs <topic>`. The five `references/*.md` files were a second copy of what the CLI now prints from inside the binary, and they went stale independently — the skill was installed from GitHub while the CLI came from npm, so the two could disagree about the same flag. Routing by topic name does not make a rename backward-compatible — the skill still names a topic, and a renamed one has to be updated there too. What changes is how that failure presents: a reference file orphaned by a skill update kept being read as though it were current, while a stale topic name cannot be served at all — the command exits 1 and says the topic is unknown, naming the closest match when one is close enough and nothing when it is not. A test now catches the stale name before it reaches anyone.

## [0.17.0] - 2026-08-11

### Changed

- Added `pdfvision docs` — the topic list and, with a topic name, its body — and cut `--help` from 20 KB to under 5 KB. The help was the first thing every agent read and the thing every error pointed at, so its size was a tax on first contact; the detail it carried now lives in fourteen topics that cost nothing until asked for. The topics are embedded at build time, so they describe the version actually installed rather than whatever the web has, and they need no network access. An unknown topic names the closest match and exits 1 instead of falling back to the list, which would read as "this topic is empty".
- Gave the trust boundary around PDF content a home the CLI can reach. `pdfvision docs security` states that everything pdfvision prints is authored by the document, what that rules out, and what `--remote`, `--password`, and `--attachment-output` each expose; `--help` now says so directly rather than leaving the topic list to be noticed. It was in the README and the bundled skill and nowhere an installed CLI could produce it, so anyone using pdfvision without the skill never saw it.
- Moved cache clearing to a `clear-cache` subcommand and stated the shape it belongs to at the top of `--help`: options are for reading a PDF, anything else is a subcommand, with `--help` / `--version` as the usual exceptions. `--clear-cache` still clears the cache and now warns; it is removed in v1.0. Terminal flags that quietly meant "do something other than read this PDF" had started accumulating their own precedence rules in the help text, and `mcp` was already on the other side of that line. Because clearing is destructive, `clear-cache` refuses rather than guessing when a file of that name exists in the working directory.
- Reported a crop-ready `region` alongside `bbox` on every `--matches-only` match, in all four formats, grown to the containing table row or visual line the way MCP's search refs already were. The evidence chain the README and `--help` recommend is a CLI flow, and it was still handing back the glyph-hugging box that renders a financial row's label without its values.
- Relayed page-level extraction warnings in `search_pdf`: a page carrying a hit and an `invisible_text`, `text_under_opaque_fill`, or glyph-garbage warning now says so, since a match is a claim about text the page may not actually show.
- Collapsed a blank form's field table to a count and a type breakdown on surfaces that request the pass on the caller's behalf (the MCP server), instead of a full-width row per empty widget. On the IRS W-9 that table was 37% of page 1 while the response budget pushed pages 4-6 out. Filled values, checked boxes, scripted widgets, and hidden/locked ones still get a row each; `--form-fields` on the CLI is unchanged. ([#162](https://github.com/yamadashy/pdfvision/issues/162))

### Fixed

- Replayed a run's warnings on a cache hit. Facts that only ever reached the caller through `onWarning` — a page range that ran past the end of the document, a per-page match cap — were dropped by every call after the first, turning an admittedly-partial answer into an apparently-complete one.
- Included `UserUnit` when fitting an MCP render to the image budget. A `/UserUnit 10` page was rasterised ten times over the limit, and the byte cap runs after the PNG exists, so it could not prevent the allocation. A page too large to fit legibly now says so and names `region` as the recovery.
- Kept both of two embedded files that share a name and a byte length. Attachment identity hashed neither, so the second `report.csv` vanished from the listing; FileAttachment annotations also overwrote each other by filename before that.
- Dropped a source's older refs when a new response files its own, which is what the ref contract already promised. A response producing five refs left `p1m5` resolvable after a later one produced only `p1m1`, so a stale handle rendered a crop from a search the caller had replaced.
- Grew a search hit's `render_pdf(ref: …)` crop to the table row or visual line it sits in, instead of padding the glyph bbox by a constant. On a financial table the old crop rendered the row label and none of its values, and a short CJK query produced an unreadable sliver. Hits the page's layout does not cover — OCR-sourced matches, pages with no reconstructed lines — keep the constant padding as the fallback. ([#159](https://github.com/yamadashy/pdfvision/issues/159))
- Mapped encrypted-PDF failures on the MCP surface to a message naming the `password` parameter, instead of relaying pdf.js's raw `No password given`. A missing password and a wrong one now read as different failures, since the recovery differs. ([#160](https://github.com/yamadashy/pdfvision/issues/160))
- Stopped telling Markdown and MCP readers to "prefer layout.blocks order" on a `reading_order_divergence` warning, when that body is already the layout-rebuilt reading order and MCP has no way to request `layout.blocks` at all. The divergence is still reported; only the remedy clause changes, and JSON, XML, and TOON keep the original wording their consumers can act on. ([#161](https://github.com/yamadashy/pdfvision/issues/161))
- Corrected the `--render-region` line in `--help`'s Common flows block, which omitted `-r` and therefore failed with `--render-region requires --render or --ocr` when typed as printed. That block exists to steer agents to the evidence chain, so a command that errors is worse than no example. ([#168](https://github.com/yamadashy/pdfvision/pull/168))
- Kept an unchecked checkbox or radio widget's row when it carries a script, a ResetForm action, `required`, `readOnly`, or a hidden / invisible / noView / locked flag. The blank-form collapse returned early on any unchecked button, so those signals were folded into the count — contradicting the documented promise that hidden and locked widgets keep a row. `invisible` now counts alongside them. ([#169](https://github.com/yamadashy/pdfvision/pull/169))

## [0.16.0] - 2026-08-09

### Added

- Added an MCP server behind `pdfvision mcp`, serving `read_pdf` / `search_pdf` / `render_pdf` over stdio for hosts without a shell (Claude Desktop, Cursor, Cline, Zed, n8n). An unscoped `read_pdf` on a long document returns a document map with next steps, search hits carry short refs that `render_pdf` accepts in place of coordinates, responses are budgeted with named follow-up calls, and remote URLs are refused when they resolve to private, loopback, link-local, CGNAT, or NAT64 addresses. ([#139](https://github.com/yamadashy/pdfvision/pull/139))
- Added `read_pdf(attachment: "name-or-index")` so an MCP caller can open an embedded file — in Factur-X/ZUGFeRD e-invoices the attachment is the authoritative data. Text attachments come back inline, images as image blocks, and opaque binaries are refused with a pointer to the CLI. ([#151](https://github.com/yamadashy/pdfvision/pull/151), follow-ups [#153](https://github.com/yamadashy/pdfvision/pull/153))
- Added `--map`: a document map (metadata, outline, per-page quality and warning codes collapsed into ranges) without page bodies — the cheap first move on an unknown document. ([#149](https://github.com/yamadashy/pdfvision/pull/149))
- Added an always-on `xfa_form` warning and `xfa` structured-output field for XFA documents, plus an `attachmentCount` presence signal for embedded files. Attachment extraction already existed; XFA content itself is not extracted. ([#101](https://github.com/yamadashy/pdfvision/pull/101))
- Added the `page_edge_text_truncated` error warning for text runs matching pdf.js's page-boundary truncation signature. The warning detects possible loss but does not recover omitted text. ([#105](https://github.com/yamadashy/pdfvision/pull/105))
- Added tagged-table reconstruction under `--structure`, with GFM table output in Markdown and inferred row/column header metadata in JSON, XML, and TOON. ([#106](https://github.com/yamadashy/pdfvision/pull/106))
- Added an always-computed `javascriptActionCount` presence signal, surfaced when non-zero, while keeping document-level action details behind `--viewer`. ([#107](https://github.com/yamadashy/pdfvision/pull/107))
- Added the `invisible_text` error warning for native text drawn with PDF text rendering mode `Tr 3`, with suppression for expected raster/OCR text layers. ([#108](https://github.com/yamadashy/pdfvision/pull/108))
- Added the conservative `text_under_opaque_fill` error warning for native text covered by later opaque dark rectangular fills. It requires positive paint-order and geometry evidence rather than claiming to detect every redaction failure. ([#109](https://github.com/yamadashy/pdfvision/pull/109))

### Changed

- Bounded regex-mode search at ~1s of regex time per page, enforced with a V8-level interrupt, so a catastrophic-backtracking pattern can no longer stall extraction: the affected page's results are dropped with a warning, an interrupted search result is never cached, and `search_pdf` relays the warning in its MCP response. ([#154](https://github.com/yamadashy/pdfvision/pull/154))
- Opened `--help` with a Common flows block naming the flagless read, the `--search … --matches-only` → `--render-region` evidence chain, and the OCR re-read, after bare-agent regression runs showed agents never scrolled to `--search`. ([#156](https://github.com/yamadashy/pdfvision/pull/156))
- TOON output follows the @toon-format/toon v4 wire format, including nested tabular headers. ([#136](https://github.com/yamadashy/pdfvision/pull/136))
- Upgraded pdfjs-dist to 6.2.108 (security release), accepting the Map-shaped viewer dictionaries it introduces. ([#143](https://github.com/yamadashy/pdfvision/pull/143))
- Reduced Markdown outline size by omitting non-actionable internal destination identifiers, and corrected the large-output hint to recommend `--outline -p 1`. Structured JSON and XML outline targets remain unchanged. ([#99](https://github.com/yamadashy/pdfvision/pull/99))

### Fixed

- Kept the `--remote` timeout active until the response body is fully consumed, so a server that sends headers and then stalls the body is aborted at the deadline instead of hanging. ([#116](https://github.com/yamadashy/pdfvision/pull/116))
- Emitted the per-page search match-cap warning only when a valid match actually exceeds the 10,000 budget, instead of firing on an exact-capacity result. ([#118](https://github.com/yamadashy/pdfvision/pull/118))
