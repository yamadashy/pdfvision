# 警告と生の密度シグナルのリファレンス

`pages[].warnings[]` には、視覚的な確認が必要なページの異常が記録されます。密度 Overview には、`quality` の元になっているページ単位の生シグナルが入ります。ここに示す JSON 形式のパスは、JSON、デコード後の TOON、`processDocument()` に対してそのまま正確です。XML については [`pdfvision docs formats`](./output.md) にあるマッピングを参照してください。[`pdfvision docs schema`](./structured-output.md) には `quality.nativeTextStatus` / `quality.visualStatus` フィールドの要約があります。このトピックは、**各生シグナルが何を意味するか** と、インラインの `warning.message` だけでは説明が足りない場合に **特定の警告コードが発火したとき何をすべきか** を調べるためのルックアップです。

`warnings[]` のコードにインラインメッセージ以上の解釈が必要なとき、または `quality` ステータスの背後にある生シグナルのしきい値を知りたいときにだけ、このページを読んでください。

この情報の機械可読な側面 — `PageWarning` の TypeScript インターフェース（`code` の union、`severity`、`message`、`blockIndex` / `otherBlockIndex` / `imageBoxIndex`）、正確な発火条件、各コードが必要とするフラグ — は、すぐ下の `## Shape` セクションにあります。

pdfvision は意図的に観測だけで止まり、行動を推奨する **ことはありません**。行動を選ぶのは、2 つの `quality` ステータスと以下の生シグナルに基づくエージェントの判断です。サイレントな失敗 — 下流の消費者には問題なく見えてしまう空の `text`、あるいは実体は NUL バイトでしかない中身の詰まった `text` — が最初から可視化されること。これが PDF を直接読むより pdfvision を使う理由です。

## Shape

```ts
interface PageWarning {
  code:
    | 'text_overlap'
    | 'near_bottom_edge'
    | 'body_near_repeated_chrome'
    | 'page_edge_text_truncated'
    | 'off_page'
    | 'glyph_garbage_text'
    | 'rtl_script_text'
    | 'localized_glyph_noise'
    | 'font_mapping_warning'
    | 'raw_embedded_source_text'
    | 'invisible_text'
    | 'text_under_opaque_fill'
    | 'dense_vector_graphics'
    | 'vector_graphics_no_native_text'
    | 'duplicate_text_layer'
    | 'raster_image_no_native_text'
    | 'tabular_numeric_layout'
    | 'dot_leader_noise'
    | 'tiny_native_text_noise'
    | 'raster_backed_text_layer'
    | 'raster_text_layer_symbol_noise'
    | 'raster_text_layer_word_fragmentation'
    | 'ocr_low_confidence'
    | 'ocr_native_text_mismatch'
    | 'ocr_native_spacing_loss'
    | 'large_raster_low_text_overlap'
    | 'annotation_text_missing_from_native'
    | 'optional_content_text_may_include_hidden_layers'
    | 'reading_order_divergence'
    | 'xfa_form';
  severity: 'warning' | 'error';
  message: string;
  blockIndex?: number;        // 0-based into pages[N].layout.blocks
  otherBlockIndex?: number;   // for pair-wise rules (text_overlap, body_near_repeated_chrome)
  imageBoxIndex?: number;     // 0-based into pages[N].imageBoxes for image-region rules
}
```

`pages[].warnings[]` は、どのルールも発火しなかった場合は省略されます。ジオメトリ系の警告はレイアウトブロックに紐づくため `--layout` が必要で、ネイティブ bbox が信頼できないほど glyph が壊れているページでは抑制されます。画像領域系の警告は、`--image-boxes` が指定されていなくても pdfvision 内部の画像ボックスパスを使うことがあります。`imageBoxIndex` が出力されるのは、公開フィールドの `pages[].imageBoxes` が存在する場合のみです。`large_raster_low_text_overlap` は、`--image-boxes` が `--layout` または `--geometry` と組み合わされている場合に、画像ボックスとネイティブテキストの bbox を比較できるため、より強い重なりの根拠を得られます。すでに `raster_image_no_native_text` が発火しているネイティブテキスト空のページでは発火しません。`tabular_numeric_layout` は、整列したレイアウト行を調べるため `--layout` が必要です。`tiny_native_text_noise` は、フォントサイズのジオメトリを調べるため `--layout` または `--geometry` が必要です。`duplicate_text_layer` は内部の span を使うため `--layout` や `--geometry` がなくても出現し得ます。肥大化したネイティブレイヤーの別々のジオメトリ症状として `off_page` や `text_overlap` と同時に出ることがあります。`annotation_text_missing_from_native` は、`--annotations` が指定されていなくても pdfvision 内部の注釈パスを使うことがあります。ただし公開フィールドの `pages[].annotations` が出力されるのは `--annotations` を指定した場合のみです。`glyph_garbage_text`、`rtl_script_text`、`localized_glyph_noise`、`font_mapping_warning`、`raw_embedded_source_text`、`invisible_text`、`text_under_opaque_fill`、`dense_vector_graphics`、`vector_graphics_no_native_text`、`dot_leader_noise`、`optional_content_text_may_include_hidden_layers` は常時有効なページ/文書レベルのシグナルを使うため、レイアウトなしでも出現し得ます。`invisible_text` と `text_under_opaque_fill` は、画像/ベクター解析ですでに取得済みのページオペレーターリストを再利用し、ラスターベースの OCR テキストレイヤーでは抑制されます。注釈の外観オペレーター、複雑なパスジオメトリ、透明・クリップ済み・ソフトマスク済み・透明グループ・optional-content の塗り、非 normal ブレンドモードの塗りは、不透明塗りの根拠から除外されます。`dense_vector_graphics` は、内部のベクターボックスジオメトリも使って、密なベクターが小さな散在装飾にすぎないテキスト優位ページを抑制できます。`raster_backed_text_layer`、`raster_text_layer_symbol_noise`、`raster_text_layer_word_fragmentation`、`raster_image_no_native_text` は内部の画像ボックスパスを使うため、`--image-boxes` が指定されていなくても出現し得ます。`ocr_low_confidence`、`ocr_native_text_mismatch`、`ocr_native_spacing_loss` には `--ocr` が必要です。`xfa_form` は文書レベルの常時有効なシグナルで、最初に抽出されたページに付与されます。

現在のルールカタログ:

- `text_overlap` — 繰り返し要素ではないレイアウトブロックが重なり、読み順を乱す可能性がある状態です。インライン数式、複数行の数式注釈、上付き文字、下付き文字、句読点のみのインライン断片、点線の地図/装飾テクスチャブロック、コールアウトマーカーの継続行による浅い隣接行 bbox の余裕は抑制されます。
- `near_bottom_edge` — 本文テキストがページ下端に不自然に近い位置で終わっています。
- `body_near_repeated_chrome` — 本文テキストが、検出された繰り返しヘッダー/フッター要素（chrome）と重なる、またはほぼ接しています。
- `page_edge_text_truncated` — 8 コードポイント以上かつ 6em 以上の抽出済みの連続テキストが、主たる書字軸に沿ってページ境界に達するか、最大 1.25em 越境しています。pdf.js がページ box の外側にある後続グリフを破棄したときの「最後に残ったグリフ」の特徴と一致します。自然な句読点による終端は抑制されます。内部の span ジオメトリにより常時有効です。レイアウトが利用可能な場合は `blockIndex` が含まれ、同一ブロックの `off_page` 検出は、このコンテンツ欠落警告を優先して抑制されます。
- `off_page` — レイアウトブロックの bbox がページ範囲を超えています。
- `glyph_garbage_text` — `quality.nativeTextStatus` が `mixed_glyph_indices` または `unusable_glyph_indices` である、あるいはネイティブテキストが Private Use Area のグリフコード文字列に支配されています。ネイティブテキストの一部または大半が生のグリフインデックスのゴミであり、使う前にレンダリングまたは OCR と突き合わせて確認すべきです。
- `rtl_script_text` — Unicode の文字が 50 個以上存在し、そのうち 25% を超えるものがヘブライ語、アラビア語、または関連する強い右書き（RTL）範囲に該当します。論理順序は保たれますが、単語間のスペースが消えたり、対になった括弧が鏡像化されたりすることがあるため、正確な文言が必要な場合はレンダリングと比較してください。
- `localized_glyph_noise` — 混在グリフのしきい値未満の複数の非印字コードポイントが出現する、Unicode 置換文字（`U+FFFD`）がそれ以外は使用可能なネイティブテキスト中に出現する、private-use のグリフコードが短い連続区間を支配する、またはそれ以外は読めるテキスト全体で繰り返される、孤立した Latin-extended の文字化けが CJK テキスト内に出現する、隣接する Latin-1 補助文字の印字可能な文字化けが短いテキスト区間を支配する、多数の隣接する CJK グリフが人為的と思われるスペースで区切られている、または隣接ペアとして重複している、あるいは `veriLJcation` のように、印字可能なフォントマップノイズが小文字の単語の中に大文字の `LJ` を挿入する、といった状態です。多くの場合、壊れた数式、比較記号、単位記号、箇条書き記号、点線リーダー、非ラテン系のカスタムフォント、アイコンフォントの記号、CJK のテキスト配置アーティファクト、テキストレイヤーの重複、リガチャ/フォントマップの置換が原因です。
- `font_mapping_warning` — ネイティブテキストは一見使用可能に見えるのに、pdf.js がフォントの文字マップデータの欠落または疑わしさを報告しました。表示上は正しく見えるテキストが、印字可能なグリフ置換として抽出されることがあるため、正確な文言が重要な場合はレンダリングと比較してください。
- `raw_embedded_source_text` — `<latexit...>` のような LaTeX 画像ソースなど、長い埋め込みプロデューサー/ソースのペイロードがネイティブテキストに混入しています。該当する `pages[].text`、レイアウトテキスト、検索一致は、レンダリングまたは OCR で確認するまで機械的な残骸として扱ってください。
- `invisible_text` — PDF のテキスト描画モード `Tr 3` が有効な状態で、1 回以上のテキスト描画オペレーションが実行されました。pdf.js はモード変更とデコード済みグリフの Unicode をページオペレーターリストで公開するため、この警告には利用可能な場合、短いサンプルが含まれます。テキストは `pages[].text` に残っていますが、人間の閲覧者には描画されません。信頼する前に `--render` と比較してください。フルページのラスターが OCR テキストレイヤーを示す場合は、通常の `raster_backed_text_layer` しきい値未満のわずかな OCR 残骸も含めて抑制されます。白色/背景色一致のテキストは、オペレーターの塗り色と粗い画像/ベクターボックスだけでは各グリフの下にある実際の背景を確実に特定できないため対象外です。
- `text_under_opaque_fill` — 3 文字以上の非空白文字を含む 1 つ以上のネイティブテキスト span が、後から描画された矩形パスの塗りによって面積の 90% 以上覆われています。この塗りは、アルファ値が 0.9〜1、輝度が 0.2 以下の暗色、ブレンドモードが normal、有効なクリップ/ソフトマスク/透明グループ/optional-content フレームなしという条件を満たします。警告には、覆われた区間の数と短いサンプルが記録されます。検出は、正規化された span を末尾から順序付けられたオペレーターリストのテキスト描画区間に整列させることで行われます。1 つの span は隣接する複数の描画区間の厳密で決定的な連結と一致することがあり、この最後の順序付き完全一致より後に描画された塗りだけが対象になります。これにより、重複排除された span が、同一の前景テキストが塗りの後に再描画された場合に誤って「隠されている」と判定されることを防ぎます。ページ上の根拠が、候補 span・テキスト描画区間・候補塗りで 4,096 件、span・生の描画区間・NFKC 正規化済み UTF-16 コード単位で 65,536 件、描画区間/コード単位の比較ステップで 1,000,000 件、span/塗りの被覆チェックで 250,000 件を超える場合、収集と照合はフェイルクローズ（安全側に倒して非検出）になります。パスデータ自体は、軸保存の CTM のもとで単一の閉じた軸並行矩形であることを証明する必要があります。複雑なパス（穴や非連結のサブパスを含む）、注釈の外観オペレーター、ストローク、薄い/半透明/透明な塗り、クリップ済み・ソフトマスク済み・透明グループ・optional-content の塗り、非 normal または解析不能なブレンドモードの塗り、下線/部分的な被覆、前景テキストより前に描画された塗り、回転またはゆがんだパス box、不正なジオメトリ、解析不能な色は無視されます。CTM、塗り色/透明度、非ストロークアルファ、ブレンドモード、クリップ、ソフトマスク、マークコンテンツの状態は、save/restore と Form XObject を通じて追跡されます。Form の BBox クリップは有効なクリップとして扱われます。検出はラスターベースの OCR テキストレイヤーでは抑制されます。`--geometry`、`--vector-boxes`、`--annotations` のいずれのフラグも不要で、この警告は `quality` を変更しません。
- `dense_vector_graphics` — ページに多数の意味のあるベクター描画オペレーションが含まれています。多くの場合、フォーム枠、表の罫線、チャートのパス、チェックボックス、ダイアグラムなど、ネイティブテキストでは表現されない可視構造です。ベクターボックスのジオメトリが利用可能な場合、多数のベクターが小さな散在装飾にすぎないテキスト優位ページは抑制されます。
- `vector_graphics_no_native_text` — 空白でないベクターのみのページにネイティブテキストがありません。記号、ダイアグラム、パスで描かれたラベルがレンダリングでは見えても `pages[].text` には存在しないことがあります。
- `tabular_numeric_layout` — 多数の短い数値行が、行位置を共有する複数の整列した列を形成しています。多くの場合、財務諸表や密な数値表で、行/列の関係が視覚的には明らかでも、プレーンなネイティブテキストではフラット化されてしまいます。チャートの軸目盛ラベルや不規則なチャートデータラベルの行は抑制されます。
- `dot_leader_noise` — 多数の単独の点線リーダー/ノイズ行が、別々のレイアウトテキストとして抽出されています。多くの場合、目次のリーダー、表のリーダー、地図のドットパターン、またはラベルを視覚的につなぐ、もしくはテクスチャを表す装飾的なドットパターンで、プレーンなネイティブテキストではノイズの多いドットの段落として現れることがあります。
- `tiny_native_text_noise` — 1 つ以上の長いネイティブテキストの連続区間が極端に小さいサイズで設定されています。多くの場合、隠れたプロデューサーのリンクや機械可読な残骸です。該当する `pages[].text`、リンク、検索一致は、レンダリングで確認するまで人間には見えない可能性があるものとして扱ってください。`--layout` または `--geometry` が必要です。
- `duplicate_text_layer` — ネイティブテキストに、一定のスケール/位置ずれを伴う、可視コンテンツの隠れたほぼ重複したレイヤーが含まれています。そのため `pages[].text` が水増しされ、レイアウトブロックが重複した連続区間を統合してしまうことがあります。正確な可視テキストが重要な場合はレンダリングまたは OCR を優先してください。`off_page` や `text_overlap` と同時に発生することがありますが、これらは別のレイアウトジオメトリのシグナルとして独立に残ります。
- `raster_backed_text_layer` — ネイティブテキストが、フルページのラスター画像の上に重なる OCR/テキストレイヤーであるように見えます。軽微な装飾的ベクターマークを伴うスキャンされた表紙の疎な OCR レイヤーも含まれます。テキストは有用な場合もありますが誤りを含みやすく、bbox/レイアウトジオメトリは人間が見るピクセルからずれることがあります。
- `raster_text_layer_symbol_noise` — ラスターベースのネイティブテキストレイヤーが、印字可能な句読点/記号のノイズに支配されています。古いスキャンの OCR タイトルページでよく見られ、`quality.nativeTextStatus` が `ok` のままでも、ネイティブテキストは明らかに信頼できません。
- `raster_text_layer_word_fragmentation` — ラスターベースのネイティブテキストレイヤーに、孤立した Latin 文字の断片が多数含まれています。古い OCR によくある失敗で、`report` のような単語が `r e p o r t` として抽出されます。正確な文言やネイティブ検索の取りこぼしは `--ocr` またはレンダリングで確認してください。
- `raster_image_no_native_text` — ラスター画像がページを支配し、ネイティブテキストが空です。画像内の人間に見えるテキストは `pages[].text` に現れません。正確な文言が必要な場合はレンダリングまたは OCR と比較してください。ネイティブテキストが空のページでは、この警告が `large_raster_low_text_overlap` を包含します。
- `ocr_low_confidence` — ネイティブ抽出が空、疎、glyph が壊れている、またはラスターベースのテキストレイヤーに乗っている状態で `--ocr` を実行し、信頼度が 0.5 未満でした。OCR テキストは存在しますが、レンダリング、言語選択、または狙いを絞ったクロップで確認するまでは暫定的なものとして扱ってください。
- `ocr_native_text_mismatch` — `--ocr` が高い信頼度で実行され、同程度の長さの短い OCR テキストが、それ以外は問題ないネイティブテキストと強く食い違っています。多くの場合、カスタムフォントが単語を正しくレンダリングする一方で、印字可能なグリフ置換として抽出されるケースです。
- `ocr_native_spacing_loss` — ラスターベースのテキストレイヤー上で `--ocr` が高い信頼度で実行され、OCR とネイティブテキストは同程度の文字を含みますが、ネイティブテキストは多くの単語境界を失っています。多くの場合、OCR は正常なスペースを復元するのに、スキャン OCR レイヤーは単語がくっついた状態で抽出されるケースです。
- `large_raster_low_text_overlap` — 大きなラスター画像がページを支配し、ネイティブテキストが空または疎である、あるいは bbox 対応の抽出で重なるネイティブテキストがほとんど見つかりませんでした。そのため、ラベル、チャートのテキスト、地図のテキスト、スクリーンショット内のテキストがネイティブテキストに現れません。すでに `raster_image_no_native_text` が発火しているネイティブテキスト空のページでは発火しません。
- `annotation_text_missing_from_native` — 1 つ以上の可視 FreeText 注釈の外観に含まれる `contents` が `pages[].text` に反映されていません。ネイティブテキストを完全なものとして扱う前に、`pages[].annotations` を読むか、`--search` / `--render-region` を使ってください。`--annotations` が出力用に指定されていなくても発生し得ます。
- `optional_content_text_may_include_hidden_layers` — ページのテキストストリームに optional-content マーク付きテキストが含まれ、かつ PDF に既定で非表示のレイヤーが 1 つ以上あります。`pages[].text` には、初期の viewer レンダリングでは表示されないレイヤーのコンテンツが含まれることがあるため、`--layers` を確認し `--render` と比較してください。
- `reading_order_divergence` — 視覚的な読み順が `pages[].text` と異なります。`layout.blocks` の先頭にある見出しがネイティブテキストストリームの後半にしか現れない場合、スライド形式で視覚的に最初に来るタイトル/ヘッダーが最後に描画され、ネイティブテキストの末尾に現れる場合、ページ下部の遅れた注記や右サイドバーがネイティブテキストの先頭に現れる場合、1 つのブロック内で再構成されたレイアウト行が順序どおりに出力されていない場合、コンパクトな数式風のブロックで、上付き文字がベースライン式の後に出力されるなど文字が並べ替えられて出現する場合、あるいは `--form-fields` によって、ネイティブテキストの順序が可視の行順序と異なるフォームラベルが露出する場合に発火します。`MM / DD / YYYY` のようなフォームの日付プレースホルダーは抑制されます。順序が重要な場合は `pages[].text` より `layout.blocks` の順序を優先してください — Markdown フォーマッターは、こうしたページでは本文をレイアウトブロックからすでに再構築しています。`--layout` が必要です。`blockIndex` は、位置がずれた見出し、スライドのタイトル/ヘッダー、遅れたブロック、局所的なブロック、またはフォームラベルのブロックを指します。
- `xfa_form` — 文書レベル: PDF が XFA（LiveCycle）フォームを宣言しており、最初に抽出されたページに付与されます。標準のテキストレイヤーは viewer のプレースホルダー（「Please wait...」）にすぎないことがあり、実際のフォームコンテンツは抽出されません。プレースホルダーのテキストは未読のコンテンツとして扱い、文書そのものとして扱わないでください。JSON/TOON/ライブラリではトップレベルの `xfa: true`、XML では `<document xfa="true">` を使います。

`quality` と同じ観測的な立場です。pdfvision はエージェントに何を見たかを伝えるだけで、それを表に出すか、再 OCR するか、`--render-region` でズームするかはエージェントが判断します。

## 密度 Overview

`result.pages.length > 1` の場合、markdown 出力はまず Overview テーブルから始まります。ページごとの `Chars / Images / Coverage / Size` に加えて、いずれかのページが回転している場合は `Rotation`、ベクター描画オペレーションを持つページがあれば `Vectors`、非印字比率が 0 でないページがあれば `NonPrint`、`--layout` が行優先の表のヒントを見つけた場合は `Tables`、`--layout` が有効だった場合は `Blocks` が加わります。`--layout` を指定すると、markdown は検出された `layout.tables[]` もページごとの `Layout tables` セクションとしてレンダリングするため、財務諸表などの数値表は、チャットで読める出力の中でも行と値の関係を保てます。

JSON、デコード後の TOON、`processDocument()` は、これらのシグナルを `overview[]` の中に `charCount` / `imageCount` / `vectorCount` / `textCoverage` / `nonPrintableRatio` / `nonPrintableCount` / `rotation` / `width` / `height` と、ネストされた `quality` として保持します。XML は `<overview><page no="..." ...>` の属性を使い、`quality` を `nativeTextStatus` / `visualStatus` にフラット化し、現状 overview の rotation は省略します。本文をスクロールする前に、まず Overview を確認してください。

## 生シグナル（`quality` への入力）

- `textCoverage: 0`（markdown では `coverage: 0%` と表示）かつ `imageCount > 0` → ページ本体がラスタライズされた画像です。テキストストリームは空です。`--ocr` または `--render` を付けて再実行してください。
- 非常に低い `textCoverage` に加えて `imageCount > 0` / `vectorCount > 0` で、かつ文字数がごくわずか → 可視ページの大部分がネイティブテキストの外にあります（`quality.nativeTextStatus === 'sparse_text_with_visual_content'`）。疎なテキストを信頼する前にレンダリングしてください。
- 非常に低い `charCount` に密なベクター構造が加わると、`textCoverage` が低くなくても `sparse_text_with_visual_content` になることがあります。1 つの大きな透かしテキスト項目がページの大部分を覆う一方で、可視のフォーム/表/チャートのコンテンツはベクターの中にある、という状況があり得るためです。
- 何らかのネイティブテキストがあり、かつ `quality.visualStatus === 'blank'` → ネイティブテキストはレンダリングされたページ上で可視ではありません（`quality.nativeTextStatus === 'sparse_text_on_blank_visual'`）。スキャンされた書籍の前付け、見えない/壊れたフォントのテキスト、レンダリング失敗でよく見られます。このテキストを人間に見える本文とみなさないでください。
- 低いテキストカバレッジを伴う `vectorCount > 0` → `imageCount` がゼロでも、ラスターではない可視構造（フォーム、チャートのパス、スライドの図形、ダイアグラム）が存在します。視覚的なレイアウトが重要な場合は `--render` で確認してください。
- `nonPrintableRatio >= 0.05` → 一部のフォントに ToUnicode CMap がないため（ヘブライ語、古い CJK、カスタム記号フォント、ブランド付き年次報告書でよくあります）、pdf.js がページの少なくとも一部で生のグリフインデックスにフォールバックしました。`0.05〜0.3` は `quality.nativeTextStatus === 'mixed_glyph_indices'` に対応し、一部のテキストは読める可能性がありますが、ネイティブ抽出は不完全です。`0.3` 以上は `unusable_glyph_indices` に対応し、ネイティブテキストはほぼゴミとして扱ってください。生のカウントは `nonPrintableCount` にあり、小数第 3 位で丸めた比率が 0 になる場合でも、このカウントを見れば非印字コードポイントが少しでも混入したかどうかが分かります（「このページにゴミが少しでもあるか」というフィルタに便利です）。正規化された `pages[].text` は、タブ/改行/復帰以外の非可視 C0 制御文字を取り除きますが、これらのカウンターは取り除く前のテキストシグナルを使うため、まばらな制御バイトの根拠も見えたままです。
- `charCount: 0` だが `imageCount: 0` → 本当に空白のページ（区切りページ、後付け）です。
- それ以外はテキストが密な文書の中で、1 ページだけ `textCoverage` が急落している → そのページは図/スキャン/チャートの可能性が高いです。`--render` で確認してください。
- `quality.visualStatus === 'sparse'` → ラスタライズされたページは空白ではありませんが、可視のマークが小さすぎる/疎すぎて視覚的にコンテンツがあるページとは呼べません。これは 1 行だけのテキストページにも、小さな画像/ベクター/注釈のマークにも当てはまります。このマークを調べるには、レンダリング失敗として扱うのではなく、オブジェクトのジオメトリ（`spans`、`vectorBoxes`、`imageBoxes`、`annotations`、`visualRegions`）または `--render-region` を使ってください。
- `quality.visualStatus === 'blank'` → ラスタライズされたページが、**そのページ自身の支配的な背景に対して** 空白になりました。多くの場合、レンダリングパイプラインの失敗（pdf.js + @napi-rs/canvas が JPEG2000 の画像ストリームをデコードできない、またはフォントに解決可能なグリフがない）か、本当に空白のページです。この比率は背景を考慮しているため、暗い色の書籍の表紙やベージュのスキャン用紙で誤検出することはありません。このページで OCR を実行すると `confidence: 0` になりますが、これは OCR が失敗したからではなく、入力がほぼ均一な画像だったためです。

## 警告カタログ（コードごとのエージェントの行動）

コードごとのフラグ要件はインラインで記載しています。ジオメトリ系の警告はレイアウトブロックに紐づくため `--layout` が必要です。テキスト品質系や画像系の警告の一部は、常時有効または内部パスに乗っているため、対応する出力フラグがなくても現れます。正確な発火/抑制条件は上の `## Shape` を参照してください。

- **`text_overlap`**（`--layout` が必要）— 繰り返し要素ではないレイアウトブロックが重なり、読み順を乱す可能性があります。`layout.blocks` の順序を優先し、順序が重要な場合は該当領域をレンダリングしてください。
- **`near_bottom_edge`**（`--layout` が必要）— 本文テキストがページ下端に不自然に近い位置で終わっています。
- **`body_near_repeated_chrome`**（`--layout` が必要）— 本文テキストが、検出された繰り返しヘッダー/フッター要素と重なる、またはほぼ接しています。
- **`page_edge_text_truncated`**（常時有効のテキストジオメトリシグナル）— 長い抽出済みテキストの連続区間が、書字軸に沿ってページ境界に達するか、わずかに越境しています。後続のグリフがページ box の外側で破棄されたときの pdf.js の特徴と一致します。ネイティブテキストが不完全な可能性があるため、ページの実際の表示内容を見るには `--render` または `--render-region` で確認してください。フラッシュ端での自然な句読点の進みは抑制されます。
- **`off_page`**（`--layout` が必要）— レイアウトブロックの bbox がページ範囲を超えています。
- **`glyph_garbage_text`**（常時有効のテキスト品質シグナル）— `quality.nativeTextStatus` が `mixed_glyph_indices` または `unusable_glyph_indices` のとき、あるいは `nonPrintableRatio` が 0 であってもネイティブテキストが Private Use Area のグリフコード文字列に支配されているときに発火します。ネイティブの `text`、`spans`、検索一致、レイアウトテキストは不完全または信頼できないものとして扱い、`--render` を確認して `--ocr` の使用を検討してください。
- **`rtl_script_text`**（常時有効のテキスト品質シグナル）— ページに Unicode の文字が 50 個以上あり、そのうち 25% を超えるものがヘブライ語、アラビア語、または関連する強い右書き範囲に該当する場合に発火します。ネイティブ抽出は論理順序のままですが、単語間のスペースが消えたり対の括弧が鏡像化したりすることがあります。正確な文言が重要な場合は `--render` と比較してください。
- **`localized_glyph_noise`**（常時有効のテキスト品質シグナル）— 混在グリフの比率しきい値未満の複数の非印字コードポイントが出現するとき、ネイティブテキストに Unicode 置換文字（`U+FFFD`）が含まれるとき、private-use のグリフコードが短い連続区間を支配するとき、CJK のページに孤立した Latin-extended の文字化けが含まれるとき、Latin-1 補助文字の印字可能な文字化けがテキストを支配するとき、多数の隣接する CJK グリフが人為的と思われるスペースで区切られているか隣接ペアとして重複しているとき、または `veriLJcation` のように印字可能なフォントマップノイズが小文字の単語の中に大文字の `LJ` を挿入するときに発火します。よくあるケース: 数式、比較記号、単位記号、箇条書き記号、点線リーダー、非ラテン系のカスタムフォント、アイコンフォント、CJK のテキスト配置アーティファクト、テキストレイヤーの重複、あるいは表示上は問題ないのに制御文字、置換グリフ、人為的なスペース、重複した CJK グリフ、または迷い込んだ印字可能グリフとして抽出されるリガチャ/フォントマップの置換。
- **`font_mapping_warning`**（捕捉された pdf.js のフォント/CMap 警告）— ネイティブテキストは一見 `ok` に見えるのに、pdf.js が文字マップデータの欠落を報告した場合に発火します。よくあるケース: カスタムの埋め込みフォントは表示上は正しいのに、印字可能なグリフ置換として抽出される。正確な文言が重要な場合は `--render` を確認してください。
- **`raw_embedded_source_text`**（常時有効のテキスト品質シグナル）— `<latexit...>` のような LaTeX 画像ソースなど、長い埋め込みプロデューサー/ソースのペイロードがネイティブテキストに混入した場合に発火します。該当する `pages[].text`、レイアウトテキスト、検索一致は、`--render` または `--ocr` で確認するまで機械的な残骸として扱ってください。
- **`invisible_text`**（常時有効のオペレーターリストシグナル）— ページに PDF 描画モード `Tr 3` で描画されたテキストが含まれます。ネイティブ抽出には含まれますが、人間の閲覧者には見えません。これは error レベルの信頼シグナルであり、サンプルおよび一致するネイティブ検索結果は `--render` と比較して確認するまで未検証として扱ってください。フルページのラスター/OCR テキストレイヤーでは抑制されます。そこでは不可視テキストが想定内であり、既存のスキャン系警告がすでにその信頼境界を説明しているためです。通常の `raster_backed_text_layer` しきい値未満のわずかな OCR 残骸も含まれます。色一致のテキスト（例: 白背景に白文字）は意図的に検出対象外です。塗り色だけでは、隠されたコンテンツと、暗い画像/ベクターパネル/非白背景ページの上にある正当な淡色テキストを十分な精度で区別できないためです。
- **`text_under_opaque_fill`**（常時有効のオペレーターリストシグナル）— 後から描画された不透明な暗色の矩形パスの塗りが span 面積の 90% 以上を覆っているにもかかわらず、ネイティブテキストは抽出可能なままです。これは error レベルの信頼シグナルで、視覚的にしか機能していない墨消し（redaction）を示している可能性があります。検出器は、最大 16 個のパス数値でエンコードされた正の矩形パスジオメトリを要求します。複雑なパス（穴のある偶奇フレームを含む）、注釈の外観オペレーター、透明な塗り、有効なクリップまたはソフトマスク、透明グループの塗り、optional-content の塗り、非 normal ブレンドモードの塗りは除外されます。隣接するテキスト描画区間は、決定的な順序付き連結によってのみ 1 つの抽出済み span に整列することがあります。抽出が同一のテキスト描画を重複排除する場合、最後の順序付き完全一致によって、その塗りが実際に後から描画されたかどうかが決まります。1 ページあたり、候補 span・テキスト描画区間・候補塗りで 4,096 件、span・生の描画区間・NFKC 正規化済み UTF-16 コード単位で 65,536 件、描画区間/コード単位の比較ステップの共有予算で 1,000,000 件、span/塗りの被覆チェックで 250,000 件を超えると、収集と整列はフェイルクローズになります。サンプルおよび一致するネイティブ検索結果は、露出した隠しコンテンツとして扱い、覆われたテキストを再利用または信頼する前に `--render` と比較してください。検出はラスターベースの OCR テキストレイヤーでは抑制されます。`--geometry`、`--vector-boxes`、`--annotations` のいずれのフラグも不要です。
- **`dense_vector_graphics`**（常時有効の `vectorCount` シグナル）— 意味のあるベクター描画オペレーションに支配されたページで発火します。多くのベクターが小さな散在装飾にすぎないテキスト優位ページは抑制されます。よくある発火ケース: フォーム、チェックボックス、表の罫線、チャートのパス、ネイティブテキストでは表現されない可視構造を持つダイアグラム。
- **`vector_graphics_no_native_text`**（常時有効の `vectorCount` シグナル）— 空白でないベクターのみのページにネイティブテキストがない場合に発火します。よくあるケース: 表示上は見えるのに `pages[].text` には現れない記号、ダイアグラム、パスで描かれたラベル。`--render`、`--vector-boxes`、`--visual-regions` で確認してください。
- **`tabular_numeric_layout`**（`--layout` が必要）— 多数の短い数値行が、行位置を共有する複数の整列した列を形成している場合に発火します。よくあるケース: 財務諸表や密な数値表で、行/列の関係は視覚的には明らかでもプレーンなネイティブテキストではフラット化されてしまいます。ラベル付きの行に繰り返しの数値列がある場合は、不規則な財務表でも検出されることがあります。チャートの軸目盛ラベルや不規則なチャートデータラベルの行は抑制されます。
- **`dot_leader_noise`**（ネイティブテキスト/レイアウトシグナル）— 多数の単独の点線リーダー/ノイズ行が別々のテキストとして抽出されている場合に発火します。よくあるケース: 目次のリーダー、表のリーダー、地図のドットパターン、ラベルを視覚的につなぐまたはテクスチャを表す装飾的なドットパターンで、プレーンなネイティブテキストではノイズの多いドットの段落として現れることがあります。
- **`tiny_native_text_noise`**（`--layout` または `--geometry` が必要）— 長いネイティブテキストの連続区間が極端に小さいサイズで設定されている場合に発火します。例えば隠れたプロデューサーのリンクなどです。該当する `pages[].text`、リンク、検索一致は、`--render` で確認するまで人間には見えない可能性があるものとして扱ってください。
- **`duplicate_text_layer`**（内部 span、フラグ不要）— ネイティブテキストに、一定のスケール/位置ずれを伴う可視テキストの隠れたほぼ重複したレイヤーが含まれている場合に発火します。これらは別のジオメトリ症状であるため `off_page` や `text_overlap` と同時に発生することがあります。正確な可視テキストが重要な場合はレンダリングまたは OCR を優先してください。
- **`raster_backed_text_layer`**（内部の画像ボックスパス、フラグ不要）— ネイティブテキストが、フルページのラスタースキャンの上に重なる OCR/テキストレイヤーであるように見えます。軽微な装飾的ベクターマークを伴うスキャンされた表紙の疎な OCR レイヤーも含まれます。テキストは有用な可能性はあるが誤りを含みやすいものとして扱ってください。認識結果が誤っていることがあり、正確なネイティブの `--search` が可視の単語を見落とすことがあり、`spans` / `layout.blocks` は人間が見るピクセルと正確には一致しないことがあります。文言や検索の再現率が重要な場合は `--ocr` を付けて再実行してください。
- **`raster_text_layer_symbol_noise`**（ラスターベースのテキストレイヤー上で）— ネイティブテキストが印字可能な句読点/記号のノイズに支配されています（例: `^`、`_`、迷い込んだ記号だらけの古いスキャン OCR タイトルページ）。`quality.nativeTextStatus` が `ok` のままでも、ネイティブテキストは特に疑わしいものとして扱ってください。
- **`raster_text_layer_word_fragmentation`**（ラスターベースのテキストレイヤー上で）— 多数の Latin 単語が孤立した文字断片に分裂しています（例: `r e p o r t`）。正確な文言やネイティブ検索の取りこぼしは疑わしいものとして扱い、レンダリングと比較するか `--ocr` で再実行してください。
- **`raster_image_no_native_text`**（内部の画像ボックスパス、フラグ不要）— ラスター画像がページを支配し、ネイティブテキストが空です。画像内の人間に見えるテキストは `pages[].text` に現れません。正確な文言が必要な場合はレンダリングまたは OCR と比較してください。ネイティブテキストが空のページでは、この警告が `large_raster_low_text_overlap` を包含します。
- **`large_raster_low_text_overlap`**（内部の画像パス、`--image-boxes` + `--layout`/`--geometry` でより強力）— 空/疎テキストの視覚的なページで、内部の画像パスが大きなラスターを検出した場合に現れます。`--image-boxes` に `--layout` または `--geometry` を組み合わせると、ネイティブテキストの bbox とラスター領域を比較し、ピンポイントのフォローアップ用に `imageBoxIndex` を含めます。すでに `raster_image_no_native_text` が発火しているネイティブテキスト空のページでは発火しません。「この画像内のラベル、チャートのテキスト、地図のテキスト、スクリーンショットのテキストには `--render` / `--render-region` / OCR が必要かもしれない」というシグナルとして扱ってください。
- **`ocr_low_confidence`**（`--ocr` が必要）— ネイティブ抽出が空、疎、glyph が壊れている、またはラスターベースのテキストレイヤーに乗っている状態で、OCR の信頼度が 0.5 未満です。OCR テキストは暫定的なものとして扱い、`--render` と比較する、`--ocr-lang` を調整する、あるいはフォームラベルや小さな文字を信頼する前にクロップして再試行してください。[`pdfvision docs ocr`](./ocr.md) を参照してください。
- **`ocr_native_text_mismatch`**（`--ocr` が必要）— OCR の信頼度が高く、ネイティブ抽出はそれ以外は `ok` なのに、OCR がネイティブテキストと強く食い違います。よくあるケース: カスタムフォントが単語を正しくレンダリングするのにネイティブテキストは印字可能なグリフ置換として抽出される、あるいはラスターベースのスキャンで高信頼度の OCR 単語の最も近いネイティブトークンが誤っている。`--render` と比較してください。ラスターベースのページでは、ネイティブ検索の見落としより OCR ベースの検索一致を優先してください。[`pdfvision docs ocr`](./ocr.md) を参照してください。
- **`ocr_native_spacing_loss`**（`--ocr` が必要）— ラスターベースのテキストレイヤー上で OCR を実行し、OCR の信頼度が高く、OCR とネイティブテキストは同程度の文字を含みますが、ネイティブテキストは多くの単語境界を失っています（`Ourwebsite` / `valuableresourcefor`）。一方 OCR は正常なスペースを復元します。正確な文言が重要な場合は `ocr.text` をレンダリングと比較してください。[`pdfvision docs ocr`](./ocr.md) を参照してください。
- **`annotation_text_missing_from_native`**（内部の注釈パス、フラグ不要）— `--annotations` がなくても、可視の FreeText 注釈の内容が `pages[].text` に反映されていません。ネイティブテキストは不完全なものとして扱い、`pages[].annotations` を読むか、`--search` を使うか、正確な可視テキストが重要な場合は注釈の bbox をレンダリングしてください。
- **`optional_content_text_may_include_hidden_layers`**（常時有効のシグナル）— ページのテキストストリームに optional-content マーク付きテキストが含まれ、かつ PDF に既定の viewer 状態で非表示のレイヤーが 1 つ以上あります。pdf.js のテキスト抽出には、人間が最初に見ないレイヤーのテキストが含まれることがあります。`pages[].text` を可視テキストとして信頼する前に `--layers` を確認し `--render` と比較してください。
- **`reading_order_divergence`**（`--layout` が必要）— 視覚的な読み順の先頭にある見出しがネイティブテキストストリームの後半にしか現れない（誌面レイアウトのフレームが順序どおりでなく出力され、ページタイトルが `text` の途中に埋もれている）、スライド形式で視覚的に最初に来るタイトル/ヘッダーが最後に描画されネイティブテキストの末尾に現れる、ページ下部の遅れた注記や右サイドバーがネイティブテキストの先頭に現れる、1 つのブロック内で再構成されたレイアウト行が順序どおりに出力されていない、コンパクトな数式テキストが視覚的な順序と異なって抽出される、あるいは `--form-fields` が、ネイティブテキストの順序が可視の行順序と異なるフォームラベルを露出する場合に発火します。順序が重要な場合は `pages[].text` より `layout.blocks` の順序を優先してください — これが JSON、XML、TOON でメッセージが伝える対処法です。Markdown（したがって MCP ツールも）は、こうしたページではすでにレイアウトから再構築した本文に切り替えているため、そちらではメッセージの内容が異なります。乖離自体は実在するが、手元のテキストはすでに視覚的な順序になっている、そして順序が重要な場合の確認手段は `--render-region` / `render_pdf` である、という内容です。
- **`xfa_form`**（常時有効の文書シグナル、最初に抽出されたページに付与）— PDF が XFA（LiveCycle）フォームを宣言しています。政府系フォームでよく見られます。動的な XFA は実際のフォームコンテンツを標準抽出では決して見えない XML ストリームに格納します。テキストレイヤーは「Please wait... upgrade Adobe Reader」のような viewer プレースホルダーだけのことが多く、報告されるページ数がプレースホルダー 1 ページに縮退することがあります。プレースホルダーのテキストから回答しないでください。文書が pdfvision では内容を抽出できない XFA フォームであることを報告し、Adobe Acrobat/Reader で開くことを提案してください。JSON/TOON/ライブラリではトップレベルの `xfa: true`、XML では `<document xfa="true">` を使います。
