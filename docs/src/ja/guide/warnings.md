# Warnings and raw density signals reference

`pages[].warnings[]` carries page anomalies that deserve visual attention, and the density Overview carries the raw per-page signals that feed `quality`. JSON-style paths here are exact for JSON, decoded TOON, and `processDocument()`; XML uses the mappings in [`pdfvision docs formats`](./output.md). [`pdfvision docs schema`](./structured-output.md) carries the `quality.nativeTextStatus` / `quality.visualStatus` field summary; this topic is the lookup companion for **what each raw signal means** and **what to do when a specific warning code fires** beyond the self-explanatory inline `warning.message`.

Read this only when a `warnings[]` code needs interpretation past its inline message, or when you want the raw signal thresholds behind a `quality` status.

The machine-readable side of this — the `PageWarning` TypeScript interface (`code` union, `severity`, `message`, `blockIndex` / `otherBlockIndex` / `imageBoxIndex`), the exact firing conditions, and which flag each code requires — is the `## Shape` section directly below.

pdfvision deliberately stops at observation: it does **not** recommend an action. The action is the agent's call based on the two `quality` statuses plus the raw signals below. Silent failures — empty `text` that looks fine to a downstream consumer, or full `text` that is actually NUL bytes — become visible up front; that is the reason to prefer pdfvision over reading a PDF directly.

## Shape

```ts
interface PageWarning {
  code:
    | 'text_overlap'
    | 'near_bottom_edge'
    | 'body_near_repeated_chrome'
    | 'page_edge_text_truncated'
    | 'off_page'
    | 'glyph_garbage_text'
    | 'rtl_script_text'
    | 'localized_glyph_noise'
    | 'font_mapping_warning'
    | 'raw_embedded_source_text'
    | 'invisible_text'
    | 'text_under_opaque_fill'
    | 'dense_vector_graphics'
    | 'vector_graphics_no_native_text'
    | 'duplicate_text_layer'
    | 'raster_image_no_native_text'
    | 'tabular_numeric_layout'
    | 'dot_leader_noise'
    | 'tiny_native_text_noise'
    | 'raster_backed_text_layer'
    | 'raster_text_layer_symbol_noise'
    | 'raster_text_layer_word_fragmentation'
    | 'ocr_low_confidence'
    | 'ocr_native_text_mismatch'
    | 'ocr_native_spacing_loss'
    | 'large_raster_low_text_overlap'
    | 'annotation_text_missing_from_native'
    | 'optional_content_text_may_include_hidden_layers'
    | 'reading_order_divergence'
    | 'xfa_form';
  severity: 'warning' | 'error';
  message: string;
  blockIndex?: number;        // 0-based into pages[N].layout.blocks
  otherBlockIndex?: number;   // for pair-wise rules (text_overlap, body_near_repeated_chrome)
  imageBoxIndex?: number;     // 0-based into pages[N].imageBoxes for image-region rules
}
```

`pages[].warnings[]` is omitted when no rule fired. Geometry warnings require `--layout` because they pin to layout blocks, and are suppressed on heavily glyph-corrupted pages where native bboxes are not trustworthy. Image-region warnings can use pdfvision's internal image-box pass even when `--image-boxes` was not requested; `imageBoxIndex` is emitted only when public `pages[].imageBoxes` exists. `large_raster_low_text_overlap` gets stronger overlap evidence when `--image-boxes` is combined with `--layout` or `--geometry`, because it can compare image boxes against native text bboxes. It is not emitted on empty-native-text pages where `raster_image_no_native_text` already fired. `tabular_numeric_layout` requires `--layout` because it inspects aligned layout lines. `tiny_native_text_noise` requires `--layout` or `--geometry` because it inspects font-size geometry. `duplicate_text_layer` uses internal spans and can appear without `--layout` or `--geometry`; it may co-occur with `off_page` or `text_overlap` because those are separate geometry symptoms of the inflated native layer. `annotation_text_missing_from_native` can use pdfvision's internal annotation pass even when `--annotations` was not requested; public `pages[].annotations` is still emitted only with `--annotations`. `glyph_garbage_text`, `rtl_script_text`, `localized_glyph_noise`, `font_mapping_warning`, `raw_embedded_source_text`, `invisible_text`, `text_under_opaque_fill`, `dense_vector_graphics`, `vector_graphics_no_native_text`, `dot_leader_noise`, and `optional_content_text_may_include_hidden_layers` use always-on page/document signals and can appear without layout. `invisible_text` and `text_under_opaque_fill` reuse the page operator list already fetched for image/vector analysis and are suppressed on raster-backed OCR text layers; annotation appearance operators, complex path geometry, transparent, clipped, soft-masked, transparency-group, or optional-content fills, and non-normal blend-mode fills are excluded from opaque-fill evidence. `dense_vector_graphics` can also use internal vector-box geometry to suppress text-dominant pages whose dense vectors are only small scattered decorations. `raster_backed_text_layer`, `raster_text_layer_symbol_noise`, `raster_text_layer_word_fragmentation`, and `raster_image_no_native_text` use the internal image-box pass and can appear even when `--image-boxes` was not requested. `ocr_low_confidence`, `ocr_native_text_mismatch`, and `ocr_native_spacing_loss` require `--ocr`. `xfa_form` is a document-level always-on signal attached to the first extracted page.

The current rule catalog:

- `text_overlap` — non-repeated layout blocks overlap in a way that may scramble reading order. Shallow adjacent-line bbox slack from inline math, multi-line math annotations, superscripts, subscripts, punctuation-only inline fragments, dotted map/decorative texture blocks, and callout-marker continuation lines is suppressed.
- `near_bottom_edge` — body text ends unusually close to the page bottom.
- `body_near_repeated_chrome` — body text overlaps or nearly touches detected repeated header/footer chrome.
- `page_edge_text_truncated` — an extracted run of at least 8 code points and 6em reaches or crosses the page boundary by at most 1.25em along its primary writing axis, matching the last-kept-glyph signature when pdf.js drops later glyphs outside the page box. Natural punctuation endings are suppressed. Always-on through internal span geometry; `blockIndex` is included when layout is available, and a same-block `off_page` finding is suppressed in favor of this content-loss warning.
- `off_page` — a layout block bbox extends beyond the page.
- `glyph_garbage_text` — `quality.nativeTextStatus` is `mixed_glyph_indices` or `unusable_glyph_indices`, or native text is dominated by Private Use Area glyph-code strings; native text is partly or mostly raw glyph-index garbage and should be checked against render/OCR before use.
- `rtl_script_text` — at least 50 Unicode letters are present and more than 25% fall in Hebrew, Arabic, or related strong right-to-left ranges; logical order is preserved, but inter-word spaces may disappear and paired brackets may be mirrored, so compare against the render when exact wording matters.
- `localized_glyph_noise` — multiple non-printable code points appear below the mixed-glyph threshold, Unicode replacement characters (`U+FFFD`) appear in otherwise usable native text, private-use glyph codes dominate a short run or repeat throughout otherwise readable text, isolated Latin-extended mojibake appears inside CJK text, adjacent Latin-1 supplement printable mojibake dominates a short text run, many adjacent CJK glyphs are separated by likely artificial spaces or duplicated as adjacent pairs, or printable font-map noise puts uppercase `LJ` inside an otherwise lowercase word such as `veriLJcation`; often broken formulas, comparison symbols, unit marks, bullets, dotted leaders, non-Latin custom fonts, icon-font symbols, CJK text-positioning artifacts, text-layer duplication, or ligature/font-map substitutions.
- `font_mapping_warning` — pdf.js reported missing or suspicious font character-map data while native text otherwise looked usable; visible text may render correctly but extract as printable glyph substitutions, so compare against the render when exact text matters.
- `raw_embedded_source_text` — long embedded producer/source payloads such as `<latexit...>` LaTeX image source leaked into native text; treat matching `pages[].text`, layout text, and search hits as machine residue until checked against render/OCR.
- `invisible_text` — one or more text-show operations ran while PDF text rendering mode `Tr 3` was active. pdf.js exposes the mode change and decoded glyph Unicode in the page operator list, so the warning includes a short sample when available. The text remains in `pages[].text` but is not painted for a human viewer; compare against `--render` before trusting it. Suppressed when a full-page raster indicates an OCR text layer, including sparse OCR residue below the normal `raster_backed_text_layer` threshold. White/color-match text is not covered because operator fill color plus coarse image/vector boxes cannot reliably establish the actual background beneath each glyph.
- `text_under_opaque_fill` — one or more native text spans of at least 3 non-whitespace characters are at least 90% area-covered by a later-drawn rectangular path fill with alpha from 0.9 through 1, dark luminance at most 0.2, normal blend mode, and no active clip, soft mask, transparency group, or optional-content frame. The warning reports the covered-run count and a short sample. Detection aligns normalized spans from the end against ordered operator-list text-show runs; one span may match an exact deterministic concatenation of adjacent runs, and only fills painted after the last ordered exact match qualify. This prevents a deduplicated span from being treated as hidden when identical foreground text was repainted after the fill. Collection and matching fail closed when page evidence exceeds 4,096 candidate spans, text runs, or candidate fills; 65,536 span, raw-run, or NFKC-normalized UTF-16 code units; 1,000,000 run/code-unit comparison steps; or 250,000 span/fill coverage checks. The path data itself must prove a single closed axis-aligned rectangle under an axis-preserving CTM. Complex paths (including holes and disconnected subpaths), annotation appearance operators, strokes, light/translucent/transparent, clipped, soft-masked, transparency-group, or optional-content fills, non-normal or unparseable blend-mode fills, underlines/partial coverage, fills painted before foreground text, rotated or skewed path boxes, invalid geometry, and unparseable colors are ignored. CTM, fill color/transparency, nonstroking alpha, blend mode, clip, soft-mask, and marked-content state are tracked through save/restore and Form XObjects. Form BBox clips are treated as active clips. Detection is suppressed on raster-backed OCR text layers. No `--geometry`, `--vector-boxes`, or `--annotations` flag is required, and the warning does not change `quality`.
- `dense_vector_graphics` — the page contains many meaningful vector drawing operations; often form boxes, table rules, chart paths, checkboxes, or diagrams whose visible structure is not represented by native text. Text-dominant pages whose many vectors are only small scattered decorations are suppressed when vector-box geometry is available.
- `vector_graphics_no_native_text` — a nonblank vector-only page has no native text; symbols, diagrams, or path-drawn labels can be visible in the render but absent from `pages[].text`.
- `tabular_numeric_layout` — many short numeric lines form multiple aligned columns with shared row positions; often financial statements or dense numeric tables whose row/column relationships are visually obvious but can be flattened in plain native text. Chart-axis tick labels and irregular chart data-label rows are suppressed.
- `dot_leader_noise` — many standalone dotted leader/noise lines were extracted as separate layout text; often table-of-contents leaders, table leaders, map stipple, or decorative dot patterns that visually connect labels or represent texture but can appear as noisy dot paragraphs in plain native text.
- `tiny_native_text_noise` — one or more long native text runs are set at extremely small sizes, often hidden producer links or machine-readable residue. Treat matching `pages[].text`, links, and search hits as possibly not human-visible until checked against the render. Requires `--layout` or `--geometry`.
- `duplicate_text_layer` — native text contains a hidden near-duplicate layer of visible content at a consistent scaled/shifted position, so `pages[].text` is inflated and layout blocks may merge duplicate runs; prefer the render or OCR when exact visible text matters. It may co-occur with `off_page` or `text_overlap`, which remain separate layout-geometry signals.
- `raster_backed_text_layer` — native text appears to be an OCR/text layer over a full-page raster image, including sparse OCR layers on scanned covers with minor decorative vector marks; text may be useful but error-prone, and bbox/layout geometry can drift from the pixels a human sees.
- `raster_text_layer_symbol_noise` — a raster-backed native text layer is dominated by printable punctuation/symbol noise; common on old scan OCR title pages where `quality.nativeTextStatus` can still be `ok` even though the native text is visibly unreliable.
- `raster_text_layer_word_fragmentation` — a raster-backed native text layer contains many isolated Latin-letter fragments, a common old-OCR failure where words like `report` extract as `r e p o r t`; exact wording and native search misses should be checked against `--ocr` or the render.
- `raster_image_no_native_text` — a raster image dominates the page while native text is empty, so human-visible text inside the image will not appear in `pages[].text`; compare the render or OCR when exact text matters. On empty-native-text pages this warning subsumes `large_raster_low_text_overlap`.
- `ocr_low_confidence` — `--ocr` ran with confidence below 0.5 while native extraction was empty, sparse, glyph-corrupted, or attached to a raster-backed text layer; OCR text is present but should be treated as tentative until checked against the render, language choice, or a focused crop.
- `ocr_native_text_mismatch` — `--ocr` ran with high confidence and short OCR text of comparable length strongly disagrees with otherwise-ok native text; often a custom font that renders a word correctly while extracting as printable glyph substitutions.
- `ocr_native_spacing_loss` — `--ocr` ran on a raster-backed text layer with high confidence, OCR and native text contain comparable characters, but native text has lost many word boundaries; often scan OCR layers that extract as glued words even though OCR restores normal spacing.
- `large_raster_low_text_overlap` — a large raster image dominates a page whose native text is empty or sparse, or bbox-enabled extraction found little overlapping native text, so labels, chart text, map text, or screenshot text inside it will not appear in native text. It is not emitted on empty-native-text pages where `raster_image_no_native_text` already fired.
- `annotation_text_missing_from_native` — one or more visible FreeText annotation appearances have `contents` that are not represented in `pages[].text`; read `pages[].annotations` or use `--search` / `--render-region` before treating native text as complete. Can appear even when `--annotations` was not requested for output.
- `optional_content_text_may_include_hidden_layers` — the page text stream contains optional-content marked text while the PDF has at least one default-hidden layer; `pages[].text` may include layer content that the initial viewer render does not show, so inspect `--layers` and compare against `--render`.
- `reading_order_divergence` — visual reading order differs from `pages[].text`. This fires when a heading that leads `layout.blocks` only appears in the back half of the native text stream, when a slide-style visually-first title/header is drawn last and appears at the end of native text, when a late bottom note or right sidebar appears at the start of native text, when reconstructed layout lines inside one block are emitted out of order, when a compact math-like block appears with reordered characters such as a superscript emitted after the baseline expression, or when `--form-fields` exposes form labels whose native text order differs from the visible row order; form date placeholders such as `MM / DD / YYYY` are suppressed. Prefer `layout.blocks` order over `pages[].text` when sequence matters — the Markdown formatter already rebuilds the body from layout blocks on these pages. Requires `--layout`; `blockIndex` points at the displaced heading, slide title/header, late block, local block, or form-label block.
- `xfa_form` — document-level: the PDF declares an XFA (LiveCycle) form; attached to the first extracted page. The standard text layer may be only a viewer placeholder ("Please wait...") and the real form content is not extracted — treat placeholder text as unread content, not as the document. JSON/TOON/library use top-level `xfa: true`; XML uses `<document xfa="true">`.

Same observational posture as `quality`: pdfvision tells the agent what it saw; the agent decides whether to surface, re-OCR, or zoom in via `--render-region`.

## The density Overview

When `result.pages.length > 1`, markdown output starts with an Overview table: `Chars / Images / Coverage / Size` per page, plus `Rotation` (when any page is rotated), `Vectors` (any page with vector drawing operations), `NonPrint` (any page with non-zero non-printable ratio), `Tables` (`--layout` found row-major table hints), and `Blocks` (`--layout` was on). With `--layout`, markdown also renders detected `layout.tables[]` as per-page `Layout tables` sections so financial statements and other numeric tables keep row/value relationships in chat-readable output.

JSON, decoded TOON, and `processDocument()` carry these signals in `overview[]` as `charCount` / `imageCount` / `vectorCount` / `textCoverage` / `nonPrintableRatio` / `nonPrintableCount` / `rotation` / `width` / `height` / nested `quality`. XML uses `<overview><page no="..." ...>` attributes, flattens `quality` into `nativeTextStatus` / `visualStatus`, and currently omits overview rotation. Read the Overview before scrolling the body.

## Raw signals (the inputs to `quality`)

- `textCoverage: 0` (rendered as `coverage: 0%` in markdown) + `imageCount > 0` → the page body is a rasterised image. The text stream is empty. Re-run with `--ocr` or `--render`.
- Very low `textCoverage` plus `imageCount > 0` / `vectorCount > 0` and only a few characters → the visible page is mostly outside native text (`quality.nativeTextStatus === 'sparse_text_with_visual_content'`). Render before trusting the sparse text.
- Very low `charCount` plus dense vector structure can also map to `sparse_text_with_visual_content` even when `textCoverage` is not low, because one large watermark text item can cover much of the page while the visible form/table/chart content lives in vectors.
- Any native text plus `quality.visualStatus === 'blank'` → the native text is not visible in the rendered page (`quality.nativeTextStatus === 'sparse_text_on_blank_visual'`). Common in scanned-book front matter, invisible/broken-font text, and failed renders; do not treat the text as the human-visible page content.
- `vectorCount > 0` with low text coverage → visible non-raster structure exists (forms, chart paths, slide shapes, diagrams) even when `imageCount` is zero. Inspect with `--render` when the visual layout matters.
- `nonPrintableRatio >= 0.05` → pdf.js fell back to raw glyph indices for at least part of the page because some fonts lack a ToUnicode CMap (common with Hebrew, older CJK, custom symbol fonts, and branded annual reports). `0.05–0.3` maps to `quality.nativeTextStatus === 'mixed_glyph_indices'`: some text may be readable, but native extraction is incomplete. `>= 0.3` maps to `unusable_glyph_indices`: treat the native text as mostly garbage. The raw count is in `nonPrintableCount` — when the 3dp ratio rounds to 0 the count still tells you whether any non-printable code points slipped through (useful for "is there ANY garbage in this page?" filters). Normalized `pages[].text` strips non-visible C0 controls other than tab / newline / carriage return, but these counters still use the pre-strip text signal so sparse control-byte evidence remains visible.
- `charCount: 0` but `imageCount: 0` → genuinely blank page (separator, end matter).
- Sudden drop in `textCoverage` on a single page in an otherwise text-dense doc → that page is likely a figure / scan / chart. Inspect with `--render`.
- `quality.visualStatus === 'sparse'` → the rasterised page is not blank, but the visible marks are too small/sparse to call the page visually populated. This can be a one-line text-only page as well as a tiny image/vector/annotation mark. Use object geometry (`spans`, `vectorBoxes`, `imageBoxes`, `annotations`, `visualRegions`) or `--render-region` to inspect the mark instead of treating this as a render failure.
- `quality.visualStatus === 'blank'` → the rasterised page came out blank **against its own dominant background**. Likely a render-pipeline failure (pdf.js + @napi-rs/canvas can't decode JPEG2000 image streams, or the font has no resolvable glyphs) or a genuinely blank page. The ratio is background-aware — dark book covers and beige scan paper don't false-trip it. OCR on this page returns `confidence: 0` not because OCR failed but because the input was a near-uniform image.

## Warning catalog (agent action per code)

Flag requirements per code are noted inline. Geometry warnings pin to layout blocks, so they require `--layout`; several text-quality and image warnings ride on always-on or internal passes and appear even without the matching output flag. See `## Shape` above for the precise firing/suppression conditions.

- **`text_overlap`** (needs `--layout`) — non-repeated layout blocks overlap in a way that may scramble reading order. Prefer `layout.blocks` order; render the region when sequence matters.
- **`near_bottom_edge`** (needs `--layout`) — body text ends unusually close to the page bottom.
- **`body_near_repeated_chrome`** (needs `--layout`) — body text overlaps or nearly touches detected repeated header/footer chrome.
- **`page_edge_text_truncated`** (always-on text-geometry signal) — a long extracted text run reaches or slightly crosses the page boundary along its writing axis, matching pdf.js's signature when later glyphs were dropped outside the page box. Native text may be incomplete; inspect `--render` or `--render-region` to see what the page actually shows. Natural punctuation advance at a flush edge is suppressed.
- **`off_page`** (needs `--layout`) — a layout block bbox extends beyond the page.
- **`glyph_garbage_text`** (always-on text-quality signal) — fires when `quality.nativeTextStatus` is `mixed_glyph_indices` or `unusable_glyph_indices`, or when native text is dominated by Private Use Area glyph-code strings even though `nonPrintableRatio` is 0. Treat native `text`, `spans`, search hits, and layout text as incomplete or unreliable; inspect `--render` and consider `--ocr`.
- **`rtl_script_text`** (always-on text-quality signal) — fires when a page has at least 50 Unicode letters and more than 25% of them are in Hebrew, Arabic, or related strong right-to-left ranges. Native extraction remains in logical order, but inter-word spaces can disappear and paired brackets can be mirrored; compare against `--render` when exact wording matters.
- **`localized_glyph_noise`** (always-on text-quality signal) — fires when multiple non-printable code points appear below the mixed-glyph ratio threshold, when native text contains Unicode replacement characters (`U+FFFD`), when private-use glyph codes dominate a short run, when a CJK page contains isolated Latin-extended mojibake characters, when text is dominated by Latin-1 supplement printable mojibake, when many adjacent CJK glyphs are separated by likely artificial spaces or duplicated as adjacent pairs, or when printable font-map noise puts uppercase `LJ` inside an otherwise lowercase word such as `veriLJcation`. Common cases: formulas, comparison symbols, unit marks, bullet symbols, dotted leaders, non-Latin custom fonts, icon fonts, CJK text-positioning artifacts, text-layer duplication, or ligature/font-map substitutions that render fine but extract as control characters, replacement glyphs, artificial spaces, duplicated CJK glyphs, or stray printable glyphs.
- **`font_mapping_warning`** (captured pdf.js font/CMap warnings) — fires when native text otherwise looks `ok` but pdf.js reported missing character-map data. Common case: a custom embedded font renders visibly but extracts as printable glyph substitutions; inspect `--render` when exact text matters.
- **`raw_embedded_source_text`** (always-on text-quality signal) — fires when long embedded producer/source payloads such as `<latexit...>` LaTeX image source leak into native text. Treat matching `pages[].text`, layout text, and search hits as machine residue until checked against `--render` or `--ocr`.
- **`invisible_text`** (always-on operator-list signal) — the page contains text drawn with PDF rendering mode `Tr 3`: it is included in native extraction but a human viewer cannot see it. This is an error-level trust signal; treat the sampled text and matching native search hits as unverified until compared with `--render`. Full-page raster/OCR text layers are suppressed because invisible text is expected there and the existing scan warnings already explain that trust boundary, including sparse OCR residue below the normal `raster_backed_text_layer` threshold. Color-match text (for example white text on white) is deliberately not detected: fill color alone cannot distinguish hidden content from legitimate light text over a dark image, vector panel, or non-white page background with acceptable precision.
- **`text_under_opaque_fill`** (always-on operator-list signal) — native text remains extractable even though a later opaque dark rectangular path fill covers at least 90% of its span area. This is an error-level trust signal and can indicate an ineffective visual-only redaction. The detector requires positive rectangular path geometry encoded in at most 16 path numbers; complex paths (including even-odd frames with holes), annotation appearance operators, transparent fills, active clips or soft masks, transparency-group fills, optional-content fills, and non-normal blend-mode fills are excluded. Adjacent text-show runs may align to one extracted span only by deterministic ordered concatenation; when extraction deduplicates identical text paints, the last ordered exact match determines whether the fill is actually later. Collection and alignment fail closed above 4,096 candidate spans, text runs, or candidate fills; 65,536 span, raw-run, or NFKC-normalized UTF-16 code units; a shared budget of 1,000,000 run/code-unit comparison steps; or 250,000 span/fill coverage checks per page. Treat the sample and matching native search hits as exposed hidden content; compare against `--render` before repeating or trusting the covered text. Detection is suppressed on raster-backed OCR text layers. No `--geometry`, `--vector-boxes`, or `--annotations` flag is required.
- **`dense_vector_graphics`** (always-on `vectorCount` signal) — fires on pages dominated by meaningful vector drawing operations. Text-dominant pages whose many vectors are only small scattered decorations are suppressed. Common firing cases: forms, checkboxes, table rules, chart paths, and diagrams whose visible structure is not represented by native text.
- **`vector_graphics_no_native_text`** (always-on `vectorCount` signal) — fires when a nonblank vector-only page has no native text. Common cases: symbols, diagrams, or path-drawn labels that render visibly but do not appear in `pages[].text`; inspect `--render`, `--vector-boxes`, or `--visual-regions`.
- **`tabular_numeric_layout`** (needs `--layout`) — fires when many short numeric lines form multiple aligned columns with shared row positions. Common cases: financial statements and dense numeric tables whose row/column relationships are visually obvious but can be flattened in plain native text. Irregular financial tables can still surface when labelled rows have recurring numeric columns; chart-axis tick labels and irregular chart data-label rows are suppressed.
- **`dot_leader_noise`** (native text/layout signals) — fires when many standalone dotted leader/noise lines are extracted as separate text. Common cases: table-of-contents leaders, table leaders, map stipple, and decorative dot patterns that visually connect labels or represent texture but can appear as noisy dot paragraphs in plain native text.
- **`tiny_native_text_noise`** (needs `--layout` or `--geometry`) — fires when long native text runs are set at extremely small sizes, such as hidden producer links. Treat matching `pages[].text`, links, and search hits as possibly not human-visible until checked against `--render`.
- **`duplicate_text_layer`** (internal spans; no flag required) — fires when native text contains a hidden near-duplicate layer of visible text at a consistent scaled/shifted position. It can co-occur with `off_page` or `text_overlap` because those are separate geometry symptoms; prefer the render or OCR when exact visible text matters.
- **`raster_backed_text_layer`** (internal image-box pass; no flag required) — native text appears to be an OCR/text layer over a full-page raster scan, including sparse OCR layers on scanned covers with minor decorative vector marks. Treat the text as potentially useful but error-prone: recognition can be wrong, exact native `--search` can miss visible words, and `spans` / `layout.blocks` may not line up exactly with the pixels a human sees. Re-run with `--ocr` when wording or search recall matters.
- **`raster_text_layer_symbol_noise`** (on raster-backed text layers) — the native text is dominated by printable punctuation/symbol noise (for example old scan OCR title pages full of `^`, `_`, and stray marks). Treat native text as especially suspect even if `quality.nativeTextStatus` is still `ok`.
- **`raster_text_layer_word_fragmentation`** (on raster-backed text layers) — many Latin words have split into isolated letter fragments (for example `r e p o r t`). Treat exact wording and native search misses as suspect; compare a render or rerun with `--ocr`.
- **`raster_image_no_native_text`** (internal image-box pass; no flag required) — a raster image dominates the page but native text is empty. Human-visible text inside the image will not appear in `pages[].text`; compare the render or OCR when exact text matters. On empty-native-text pages this warning subsumes `large_raster_low_text_overlap`.
- **`large_raster_low_text_overlap`** (internal image pass; stronger with `--image-boxes` + `--layout`/`--geometry`) — appears on empty/sparse-text visual pages when the internal image pass sees a large raster. With `--image-boxes` plus `--layout` or `--geometry`, it compares native text bboxes against raster regions and includes `imageBoxIndex` for pinpoint follow-up. Not emitted on empty-native-text pages where `raster_image_no_native_text` already fired. Treat it as "labels, chart text, map text, or screenshot text inside this image may need `--render` / `--render-region` / OCR."
- **`ocr_low_confidence`** (needs `--ocr`) — OCR confidence below 0.5 while native extraction is empty, sparse, glyph-corrupted, or riding on a raster-backed text layer. Treat OCR text as tentative; compare with `--render`, adjust `--ocr-lang`, or crop/retry before trusting form labels or small print. See [`pdfvision docs ocr`](./ocr.md).
- **`ocr_native_text_mismatch`** (needs `--ocr`) — OCR confidence is high, native extraction is otherwise `ok`, and OCR strongly disagrees with native text. Common cases: a custom font renders a word correctly while native text extracts as printable glyph substitutions, or a raster-backed scan has high-confidence OCR words whose nearest native tokens are wrong. Compare against `--render`; for raster-backed pages, prefer OCR-backed search hits over native search misses. See [`pdfvision docs ocr`](./ocr.md).
- **`ocr_native_spacing_loss`** (needs `--ocr`) — OCR ran on a raster-backed text layer, OCR confidence is high, OCR and native text contain comparable characters, but native text has lost many word boundaries (`Ourwebsite` / `valuableresourcefor`) while OCR restores normal spacing. Compare `ocr.text` with the render when exact wording matters. See [`pdfvision docs ocr`](./ocr.md).
- **`annotation_text_missing_from_native`** (internal annotation pass; no flag required) — visible FreeText annotation contents are not represented in `pages[].text`, even without `--annotations`. Treat native text as incomplete; read `pages[].annotations`, use `--search`, or render the annotation bbox when exact visible text matters.
- **`optional_content_text_may_include_hidden_layers`** (always-on signal) — the page text stream contains optional-content marked text and the PDF has at least one layer hidden in the default viewer state. pdf.js text extraction can include text from layers a human does not initially see; inspect `--layers` and compare against `--render` before trusting `pages[].text` as the visible text.
- **`reading_order_divergence`** (needs `--layout`) — a heading that leads the visual reading order only appears in the back half of the native text stream (magazine-style frame layouts emitted out of order — the page title buried mid-`text`), a slide-style visually-first title/header is drawn last and appears at the end of native text, a late bottom note or right sidebar appears at the start of native text, reconstructed layout lines inside one block are emitted out of order, compact math text extracts out of visual order, or `--form-fields` exposes form labels whose native text order differs from the visible row order. Prefer `layout.blocks` order over `pages[].text` when sequence matters — that is the remedy the message carries in JSON, XML, and TOON. Markdown (and therefore the MCP tools) already switches to the layout-rebuilt body on these pages, so there the message says so instead: the divergence is real, the text you are holding is already the visual order, and `--render-region` / `render_pdf` is the confirmation step when sequence is critical.
- **`xfa_form`** (always-on document signal, attached to the first extracted page) — the PDF declares an XFA (LiveCycle) form, common in government forms. Dynamic XFA stores the real form content in an XML stream that standard extraction never sees: the text layer is often only a "Please wait... upgrade Adobe Reader" viewer placeholder and the reported page count can collapse to one placeholder page. Never answer from the placeholder text; report that the document is an XFA form whose content pdfvision does not extract, and suggest opening it in Adobe Acrobat/Reader. JSON/TOON/library use top-level `xfa: true`; XML uses `<document xfa="true">`.
